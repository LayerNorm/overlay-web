# File-native Harness rollout

File-native upload, original-file reading, resilient retrieval, and partitioned
analysis are independently gated by the server-evaluated flags
`files-file-first`, `files-reading-tools`, `files-hybrid-retrieval`, and
`harness-file-analysis`. Enable them in this order:

1. `files-file-first`
2. `files-reading-tools`
3. `files-hybrid-retrieval`
4. `harness-file-analysis`

The web application and backend must be coordinated in an isolated preview.
Legacy files need no migration. Disabling a flag stops the corresponding
behavior but leaves stored originals and derived text intact.

The source object is immutable and identified by its SHA-256 revision.
Extraction and indexing are separate statuses; a completed upload means the
original is available, not that extraction or search indexing has completed.
Failed extraction can be retried through the existing ingestion endpoint
without creating a second file or charging quota again. Derived text is stored
separately and capped at 10 MiB; truncated text is labeled as incomplete.

`read_document` uses the authorized Computer and is currently limited to PDF
page reading, rendering, candidate-table extraction, and optional OCR. It
prepares a dedicated Python environment with PyMuPDF 1.26.7. OCR additionally
requires Tesseract on the Computer. Table detection and OCR are candidates
that require human/model verification; neither is a guarantee of correctness.
Rendered images are bounded, and missing or unreadable pages must be reported
as missing rather than treated as evidence of absence.

Harness checkpoints retain short tool observations when they fit the existing
7,500-byte checkpoint budget. Larger observations remain marked as truncated;
use `harness_read_evidence` to inspect persisted details before treating missing
preview text as missing source data. Image artifacts still require authorized
reopening and visual inspection, not an inference from render metadata.
Document evidence preserves observed page counts, pixel dimensions, and image
format without embedding binary data. These facts support render-metadata claims
in final verification, not claims that the image was visually inspected.
Use `harness_revise_step` to change one existing milestone definition; unchanged
milestones retain their evidence and completion state, while the existing plan
validation and invalidation rules still apply. Repeated planning repairs are
bounded to four model steps without new successful tool-result evidence. The
counter survives checkpoints, resets on new evidence, and pauses truthfully at
the limit. Repair bookkeeping is removed from public progress, transcript,
delivery and native streaming without hiding ordinary plan discussion or code.

Hybrid file retrieval falls back to lexical results when embedding pricing,
reservation, or provider calls fail. It preserves provider reservation and
reconciliation rules. Lexical chunks exist before vector indexing; the file's
`indexStatus` describes lexical readiness and `semanticIndexStatus` describes
vector readiness. Results exclude deleted, inaccessible, and stale sources.
Bounded same-source neighbors follow primary results without displacing them.

`read_file` returns bounded 60,000-character ranges over the BFF, with offsets,
total extracted characters, and completeness. Its write-concurrency `revision`
remains the update timestamp; `sourceRevision` is the original SHA-256.

`harness_analyze_files` uses existing durable Harness children, shared budgets,
cancellation, concurrency and depth limits, rather than a separate model billing
path. A call assigns up to 32 versioned ranges of up to 20 pages each. Assignments
cannot overlap within a call; the parent must avoid overlap between calls.
Feature evaluation is persisted as a workflow step, not trusted from tool input.
Children inherit only the intersection of their parent's tools and reading,
search and Computer capabilities. Computer execution remains a general capability;
the analysis instructions do not constitute an additional filesystem sandbox.

`harness_read_child` returns coverage derived from persisted successful
`read_document` observations, including descendants. Metadata, table candidates,
blank or truncated text, arbitrary child prose, and wrong revisions do not count
as page coverage. Missing, stale and unavailable pages are separate. Coverage
means observed pages, not proven comprehension. Exact counts require deterministic
code over observed records. The coverage scan is bounded to 128 descendant runs
and the most recent 1,024 observations per run; hitting either limit prevents a
complete-coverage claim. Completed child work is reused on replay.

## Preview acceptance

Public progress is a separate, tool-free call capped at 256 output tokens, not
an execution result or final answer. Simulated tool calls invalidate that progress
step for saved transcripts and subsequent model history, while its actual usage
still settles. Function-call XML is hidden from live delivery. Real document
observations and final-answer verification remain required for acceptance.

The latest hosted failure showed a valid PDF read and render followed by
unrelated completed milestones being reopened by full-plan rewrites; repair
prose also reached public text and final verification was not reached. Targeted
milestone revision and bounded private repair are implemented locally, but a
hosted rerun is still needed to validate recovery through final verification.

- Upload a PDF larger than 4.5 MB with file-first enabled; its original must remain
  downloadable if extraction fails. Retry registration without uploading again.
- Read a multi-page PDF, a scanned page and a table on a provisioned Computer.
  Check revision/page citations and missing OCR capability reporting. Shared-room
  original reads are currently withheld; non-PDF files use extracted text tools.
- Test exact IDs, semantic paraphrases, stale/deleted files and inaccessible
  workspace files. Disable embedding capacity and verify lexical-only metadata.
- Interrupt a partitioned analysis, resume it, and verify no completed child is
  relaunched and missing pages never become exhaustive results.
- Compare correctness, evidence, latency and total cost before enabling flags
  beyond the isolated preview. No flag defaults are changed by this feature.
