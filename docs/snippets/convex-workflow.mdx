Treat matching web and Convex revisions as one release unit. Local development
uses an engineer-owned backend; feature worktrees never deploy shared environments.
PR previews deploy only their per-PR backend.

After main changes, Production Release dispatches dedicated staging acceptance,
then publishes and verifies production web before deploying production Convex and
running authenticated smoke. The legacy staging branch is frozen.

For authorized manual recovery, use the guarded command from clean current
canonical main:

```bash
bash scripts/release/promote.sh <exact-main-sha>
```

Never use `convex:push:all` or pass `.env.local` to production. See
[Staging and Production Promotion](/develop/worktree-staging-qa) for credentials,
exact-SHA acceptance and rollback.
