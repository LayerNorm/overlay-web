Rehearsal 4 validates the P4 knowledge data plane on AWS. A Neon or local run is useful characterization, but it is not an AWS rehearsal. The gate intentionally rejects database hosts that are not RDS or Aurora endpoints.

## Prerequisites

- The AWS rehearsal branch contains P4a through P4e from `codex/on-prem-parity`.
- RDS PostgreSQL or Aurora PostgreSQL exposes the `vector` extension.
- The test database is disposable and uses a dedicated role.
- `OVERLAY_DATABASE_URL` uses the unpooled writer endpoint.
- `OVERLAY_DATABASE_SSL_MODE=verify-full` and the runtime trusts the AWS CA bundle.
- One app task, one worker task, and one scheduler task use the same release image and config.

## Run The Automated Gate

Export the rehearsal database and provider configuration in the shell used by the AWS agent. Do not commit credentials.

```bash
export OVERLAY_DATABASE_URL='postgresql://...rds.amazonaws.com/overlay_rehearsal'
export OVERLAY_DATABASE_SSL_MODE=verify-full
export OVERLAY_PROVIDER_VECTOR_SEARCH=pgvector
export OVERLAY_PROVIDER_EMBEDDINGS=openai
export OVERLAY_EMBEDDING_MODEL_VERSION=text-embedding-3-small-v1
export OPENAI_API_KEY='...'
npm run aws:rehearsal:4
```

The command applies migrations, runs P4d crash/recovery and lifecycle contracts, runs the fixed-corpus pgvector characterization, then verifies the endpoint class, TLS mode, schema version, installed pgvector version, and durable knowledge job state.

## Runtime QA

1. Create a memory from a completed chat turn and confirm `memory.extract-turn` completes after a worker replacement.
2. Upload a text file globally and another into Project A. Confirm both become searchable.
3. Add a different marker to Project B. Query for it from Project A and confirm it is absent.
4. Repeat the marker attack from another test account and confirm it is absent.
5. Stop the worker after it leases `knowledge.reindex-source`, wait for lease expiry, and start a replacement worker. Confirm the source becomes indexed once.
6. Change the embedding model version, run `npm run app-db:knowledge-backfill -- --limit=2000`, and drain jobs before retiring the old model.
7. Delete a memory, file, project, and account. Confirm source rows, chunks, embeddings, and extraction audit rows are removed according to their ownership and retention rules.
8. Inspect dead-letter jobs and failed source statuses. Repair the cause, run maintenance, and confirm recovery requeues them.

## Browser QA

- Memories list, create, edit, refresh, and delete without Convex requests.
- File search returns the correct source and opens it.
- Project chat retrieval includes global plus same-project sources, never another project.
- Citation chips open the file or memory identified by the server citation map.
- Refresh preserves results; deletion removes the item and it does not return after refresh.

Capture CloudWatch logs for app, worker, and scheduler tasks, the fixed-corpus metrics, job queue state, RDS performance metrics, and the final cleanup queries as the rehearsal artifact.
