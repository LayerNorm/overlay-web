Overlay Files on every computer

Every folder an agent can use, whether it lives in Overlay, Google Drive, GitHub or on one of your Macs, appears in Files and can be picked for a thread. Cloud computers mount Overlay Files at /overlay and copy code into /workspace. Every save still goes through Overlay, so search and permissions work the same as in the app.

Documents: mounted, every save through Overlay Code: copied, changes back as a pull request Tool calls from the agent

Three rules

Mount for documents

Notes, docs, spreadsheets and data appear at /overlay, so ls, cat and grep just work.

  • Every save goes through the file service, never straight into storage.
  • A note edited by someone else in the meantime is saved as a copy, never overwritten.
  • Drive folders go through the same path, so Drive sign-ins stay on the server.

Copy for code

Builds touch thousands of small files, which is slow over a mount. Code is copied to /workspace instead.

  • GitHub: clone, work on a branch, open a pull request. Never pushes to main.
  • Overlay folder: copied in, and copied back when the work is done.
  • One writer at a time, so nothing needs two-way sync.

Every Mac is a computer too

The same harness sends the same tools to any of your Macs with the desktop app. You can start and watch a thread from anywhere, including the web.

  • A Mac folder belongs to one Mac, so a thread using it runs only on that Mac. Offline Macs can’t be picked.
  • Mac folders are edited in place and never uploaded on their own.
  • “Copy to Files” turns a Mac folder into an Overlay folder that cloud agents can use.
  • Later, Finder can mount the same WebDAV endpoint.

Why not mount the storage bucket directly

  • The names would be wrong. Storage holds files under random keys. Folder names and the tree live in Convex, and most notes aren’t in storage at all.
  • It would skip what Files does on save: search, scope, permissions, note checks and agent attribution.
  • It can’t be scoped. Keys aren’t grouped by person or workspace, so a computer would see everyone’s files or none.
  • It isn’t a real disk. No atomic renames, slow listings, and no safety when two writers touch one file.

Build order

  1. Check that a cloud computer can mountConfirm FUSE on a preview Boat computer. If it isn’t allowed, copy in and out everywhere instead.
  2. Read-only WebDAVFolder listings and downloads from the file service with per-computer access, then rclone mount on a computer. Measure ls, cat and grep on about 1,000 files.
  3. SavesThrough the normal save path, with the note conflict rule and “edited by agent”.
  4. A thread works in a folderThe folder picker under the composer. The computer mounts /overlay and makes the /workspace copy.
  5. Connected sourcesDrive folders through the same endpoint, GitHub repositories through git, and “Copy to Files” from any Mac.

Open decisions

  • What an agent’s computer mounts. Proposed: workspace files only. Your personal files stay off it, matching today’s rule for shared threads.
  • Whether agents can save into /overlay by default. Proposed: yes. Agent edits are marked, and a file someone else changed meanwhile is saved as a copy. Files has no version history yet; adding it would make this safer.
