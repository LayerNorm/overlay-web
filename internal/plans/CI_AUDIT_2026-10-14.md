# CI audit — 2026-10-14

Status: implemented and locally verified on 2026-10-14. Hosted timing and
publication evidence belong to the exact commit's GitHub/Vercel runs.

## Implementation

The serial quality job is replaced by static, compilation and two test-shard
jobs, followed by an always-run aggregate that rejects failures, cancellation,
missing results and unexpected skips. All nine required contexts are retained.
Gateway contracts share a test worker and report through their original context.
Docs runs on every main push, allowing removal of duplicate docs health from the
quality job. CodeQL no longer installs unrelated npm dependencies; Semgrep's
currently used version is pinned with pip caching. Four internal-document links
now point to their canonical repository files.

The CI build omits its duplicate TypeScript pass, with current route validators
generated in the independently required static job. All original explicit test
commands and their runtime settings remain; tests with distinct execution settings
were not discarded merely because their filenames also occur in full discovery.
Two shards partition the complete discovery inventory, retaining atomic package
build/test commands. No path-based test exemptions or result reuse were introduced.
The findings and timings below describe the pre-change baseline.

### Local verification

- All 447 original tracked test files remain; the new shard tests bring discovery
  to 448. Both shards passed. Their partition is complete and disjoint.
- Twelve workflow/sharding regression tests passed, including every lane's
  failed/cancelled/skipped/missing result, merge-group dependency review and
  valid post-main dependency-review exemption. Invalid and empty runner selections
  fail.
- Hosted Semgrep caught a missing cooldown in the new pip Dependabot entry. It
  now uses the same seven-day cooldown as the other ecosystems. Scans print
  human-readable findings and upload SARIF after findings fail the job, retaining
  blocking behavior; a regression test covers both contracts.
- Full lint passed (existing warnings), fresh `next typegen` plus the existing
  `npm run typecheck` passed, and the production build exited successfully with
  the separately checked TypeScript pass omitted.
- Route/gateway contracts, complexity, configuration, release safety, tenant
  boundaries, post-build Convex inventory and the production dependency audit
  passed. Documentation generation, health, Mintlify validation and broken links
  passed. The generated API document was refreshed to include the already-shipped
  Work resource in its resource enum.
- `actionlint` validated all workflows; diff whitespace validation passed.

This verifies preserved checks, not the projected hosted speedup. No branch rules,
Vercel machine settings, Preview automation or production credentials changed.

## Evidence and measurement

Inspected the workflow definitions, package scripts, test discovery script,
current main rules, and eight recent runs each of Security Checks, Docs, Gateway
Contracts, CodeQL, Semgrep, PR Preview and Docker publication (56 run records,
including running, skipped and failed runs). Downloaded selected completed logs.
These are a small recent sample, not long-term percentiles.

The principal required job, **Required Quality and Security Gates**, took
413, 488 and 596 seconds in three successful runs: approximately 7–10 minutes.
Queue delay was generally 2–5 seconds in those runs; one current burst had
97–108 seconds of delay in Security Checks. Runner contention exists, but does
not explain the successful baseline alone. More parallel jobs must be bounded
by actual available runner capacity.

The security gate steps run sequentially. Other workflow jobs run alongside it.
Do not add all table rows together to estimate user wait. Docker publication is
post-main work, not a required PR merge check. Preview readiness is part of QA,
but is not among the nine required GitHub ruleset contexts.

The main merge queue checks the combined candidate again. That repetition tests
a different revision and protects against interacting PRs; it is not disposable
duplicate work. Main push checks also protect the authorized direct-push path.

## Confirmed redundant work

1. **Repeated TypeScript checking.** The standalone typecheck is followed by
   Next's internal TypeScript pass. The 413-second run spent another 40 seconds
   checking TypeScript inside its build. A separate build can use the existing
   `OVERLAY_SKIP_BUILD_TYPECHECK=1` switch only when an independent required
   typecheck covers the same candidate and generated route types. Generate types
   before standalone checking; do not rely on stale `.next/types`.
2. **Repeated tests.** `npm run typecheck` runs chat, knowledge, showcase and
   desktop-boundary test commands before `tsc`. The full suite discovers those
   files again. Route-characterization, release-safety and configuration test
   commands also repeat files included in the full suite. Keep their non-test
   boundary/configuration validators, and preserve each distinct test environment
   or runner requirement when consolidating execution.
3. **Gateway contracts run twice.** The six explicit gateway contract test files
   are also discovered by the full test runner. The dedicated workflow installs
   the entire workspace to run about 9–11 seconds of tests. Retain the required
   check name through a trustworthy aggregate/result job if removing this lane.
4. **Documentation health runs twice.** The main gate invokes `docs:health`, and
   `docs:check` invokes it again. The validator is very fast; this is a lower
   priority than its separate 40–67-second dependency installation.
5. **CodeQL setup is heavier than needed for handwritten JS/TS.** The workflow
   installs all npm dependencies before analysis. Evaluate analysis without that
   installation and no-op autobuild, preserving the scanned source inventory,
   generated-code requirements and existing queries. Its observed autobuild took
   negligible time, so do not claim that it currently performs another Next build.
6. **Repeated setup.** npm download caching is already enabled, but each Node job
   still performs a clean installation. There is no explicit Next build-output or
   TypeScript build-info cache in the inspected workflows. Do not blindly share
   executable dependency artifacts between untrusted and privileged workflows.

## Recommended implementation order

1. **Repair existing failures first.** Four broken Mintlify links currently block
   dependency PRs #161, #168 and #177. Example
   [failed Docs run](https://github.com/LayerNorm/overlay-web/actions/runs/38610843403):
   `develop/worktree-staging-qa.mdx`,
   `plans/RELEASE_WORKFLOW_MIGRATION_PLAN.md`, and
   `plans/RELEASE_WORKFLOW_TARGET.md`. #177 also currently fails Dependency Review;
   inspect its actual advisory before considering acceptance. Do not mark these
   checks successful merely to reduce wait.
2. **Split the serial quality gate into bounded parallel lanes:** static checks
   and types; production compilation; complete test execution; docs/security.
   Keep the existing required aggregate check, failing closed on any failed,
   cancelled or unexpectedly missing constituent. Preserve all nine required
   contexts or migrate protections atomically.
3. **Consolidate repeated tests and type checking** with a checked inventory of
   commands, test files and execution conditions. Keep every distinct assertion.
4. **Split the largest test group if still worthwhile.** Of 447 files, 389 run
   in the `tsx` group, which consumed 90–141 seconds in two logs. The other five
   groups are much smaller. Shard the large group into a small bounded matrix;
   check that the union equals the complete discovery manifest, reject empty or
   invalid shard selections, and preserve any fixture isolation requirements.
5. **Optimize setup and scanners:** remove unnecessary CodeQL installation after
   proving equivalent source coverage; pin/cache Semgrep installation; consider
   safe Next/TypeScript caches with keys including toolchain/configuration and
   dependency changes. Measure cache restore/upload costs before retaining them.
6. **Add conservative change classification last.** Documentation-only changes
   can avoid app compilation/tests if no application, dependency, generation or
   CI inputs changed. Unknown classifications run everything. Keep an always-run
   required aggregate so path filters cannot leave checks pending. Dependency,
   workflow, shared configuration and mixed changes receive full coverage.

Keep CodeQL and Semgrep: they overlap, but this audit does not prove equivalent
coverage. Keep dependency review plus the installed production dependency audit:
one checks changes, the other checks the current installed tree. Keep combined
merge-group checks and meaningful post-main verification. Cancel superseded PR
work safely; existing ordinary check workflows already do this. The trusted
preview controller deliberately serializes operations per PR and must not be
cancelled mid-cleanup without checking its lifecycle guarantees.

## Expected benefit and acceptance

A reasonable initial target is **3–5 minutes per required-check round**, versus
the sampled 7–10 minutes. This is a design estimate, not a measured improvement;
runner contention, CodeQL and Vercel readiness may still dominate. Parallelism can
increase runner minutes even when wall-clock wait falls. Avoid splitting every
small validator into its own installation-heavy job.

For implementation acceptance: compare the complete test manifest and execution
conditions before/after; demonstrate that deliberate lint/type/test/build/security
failures still block the aggregate; exercise PR and merge-group triggers; verify
docs-only and dependency classifications; measure several comparable runs with
queue time separated from execution. This audit listed tests and inspected saved
results; it did not execute the test suite or modify protections.
