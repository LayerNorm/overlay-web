# Web API route catalog

This is the route-entry-point inventory for the web app. It is intended as a working catalog for monitoring, security review, contract testing, and incident response.

## Scope and reading guide

- External-agent setup and new execution require `OVERLAY_FEATURE_EXTERNAL_AGENTS` plus the existing control-plane, remote-run/cloud and workspace rollout gates. The master gate defaults off for the native-Overlay-only launch. Authorized history, cancellation, revocation, machine teardown and host settlement paths remain available without authorizing new starts. Native `/api/v1/computers` uses its own independent capability. See `FEATURES.md` at the repository root and the living Bring Your Own Agents guide for re-enablement.

- Source of truth for route existence: every `src/app/api/**/route.ts` file. The inventory contains 214 route entry points: 42 non-versioned routes and 172 `/api/v1` routes. Test files are not endpoints.
- Next.js dynamic segments are shown in the same notation as the source: `[id]` and `[...path]`.
- Most user-facing `/api/v1` requests pass through `src/app/api/v1/_utils/bff.ts`, which authenticates the caller, parses the request, resolves workspace context, applies route policy/idempotency/rate-limit behavior, and delegates to the server implementation. Direct routes and internal callbacks are marked below; the per-route file list names the transport entry point and the implementation or direct service files.
- `src/server/app-api/v1/**/route.ts` is server-only domain logic, not a second public URL. Where the app route delegates directly to another app route, that is called out explicitly.
- Explicit workspace routes and active-workspace headers return 404 when the caller no longer has access; neither falls back to another workspace.
- “Authenticated” means the BFF/app auth resolver accepts a browser session, supported bearer token, or API key for that route. “Host-authenticated” means the connected-agent request signature and exact environment binding are required. “Internal” means the internal service secret is required.
- Unexpected agent-environment failures return a generic no-store 500 with `x-overlay-diagnostic-id`, matching the safe server diagnostic and Sentry event id. Host poll/events/ack/heartbeat routes also return `x-overlay-request-id` for host-to-server correlation. Expected control-plane and validation rejections retain their existing status and response contract.
- The generated OpenAPI file is intentionally incomplete for several legacy, streaming, extension, admin, and connected-agent routes; this catalog is broader than `docs/openapi/overlay-web.openapi.json`.

## 1. Authentication, sessions, account, and cross-surface handoff

- `PATCH /api/v1/account/profile` — Updates the signed-in person's display-name override or resets their photo, returning the profile. The browser reads the profile live from the native `auth/accountBrowse:identity` query. Files: `src/app/api/v1/account/profile/route.ts`; `src/server/app-api/v1/account/profile/route.ts`.
- `GET, POST /api/v1/account/profile/photo` — Reads an authorized profile photo or accepts a multipart `file` upload after account authorization. Files: `src/app/api/v1/account/profile/photo/route.ts`; `src/server/app-api/v1/account/profile/photo/route.ts`; `src/server/app-api/v1/account/profile/route.ts`.

- `POST /api/auth/preview-login` — Preview-only QA authentication. Requires both preview deployment markers, a canonical PR origin, Overlay's sandbox WorkOS client, a configured identity, and a timing-safe header secret check before provider access. Defaults to the server-configured owner; optional `x-overlay-preview-identity: member` or `outsider` selects only the corresponding preconfigured sandbox credentials. Rejects unknown roles, arbitrary identities and unverified users, verifies the returned user ID before creating the ordinary encrypted session, rate-limits authenticated attempts, and returns no tokens. Returns 404 on staging/production or invalid configuration. Files: `src/app/api/auth/preview-login/route.ts`; `src/server/auth/preview-login.ts`; `src/server/auth/preview-login-policy.ts`; `src/shared/web/preview-origin.ts`.
- `POST /api/account/delete` — Authenticates the current web user, verifies same-origin confirmation, rate-limits the operation, deletes account data through the configured provider, and clears the session. Files: `src/app/api/account/delete/route.ts`; `src/server/account/AccountDeletionService.ts`; `src/server/auth/app-api-auth.ts`; `src/server/auth/session.ts`; `src/server/security/rate-limit.ts`.
- `GET /api/auth/callback` — Completes the configured browser SSO callback after consuming one-time authorization state, upserts the user, and redirects to the requested web or native handoff destination. Files: `src/app/api/auth/callback/route.ts`; `src/server/auth/actions.ts`; `src/server/auth/session.ts`; `src/server/auth/session-transfer-crypto.ts`; `src/server/database/convex.ts`.
- `GET /api/auth/convex-policy` - Internal Convex policy callback. Requires the shared internal API secret and a valid refresh challenge, returns the backend-bound policy resolved from current web configuration with no-store caching, and fails closed when unavailable. It does not accept browser policy overrides. Files: `src/app/api/auth/convex-policy/route.ts`; `src/server/authorization/native-deployment-policy.ts`.
- `GET /api/auth/convex-token` — Returns the web session’s verified provider access token for native Convex auth, only when its subject is the session user. Files: `src/app/api/auth/convex-token/route.ts`; `src/server/auth/native-convex-token.ts`; `src/server/auth/session.ts`.
- `POST, GET /api/auth/desktop-link` — Creates a short-lived, PKCE-bound desktop/Chrome session-transfer deep link, or consumes that one-time token when the client presents the verifier. The desktop web shell redeems the same token in its window through the page route `GET /auth/desktop/complete` (verifier in the `x-overlay-code-verifier` header), which sets the normal session cookie instead of returning tokens (`src/app/auth/desktop/complete/route.ts`, `src/server/auth/desktop-web-session-policy.ts`). Files: `src/app/api/auth/desktop-link/route.ts`; `src/server/auth/session-transfer-crypto.ts`; `src/server/auth/actions.ts`; `src/server/database/convex.ts`; `src/server/shared/internal-api-secret.ts`.
- `POST /api/auth/forgot-password` — Validates and rate-limits a password-reset request, delegating delivery and provider-specific behavior to the auth actions layer. Files: `src/app/api/auth/forgot-password/route.ts`; `src/server/auth/actions.ts`; `src/server/security/rate-limit.ts`.
- `POST /api/auth/native/authorize` — Validates native PKCE state, redirect URI, provider, capability, and rate limits, then returns the server-owned authorization URL. Files: `src/app/api/auth/native/authorize/route.ts`; `src/server/auth/actions.ts`; `src/server/auth/native-auth-validation.ts`; `src/server/security/rate-limit.ts`; `src/server/capabilities.ts`.
- `POST /api/auth/native/exchange` — Validates a native authorization code and PKCE verifier, exchanges them for a native session, and synchronizes the user profile. Files: `src/app/api/auth/native/exchange/route.ts`; `src/server/auth/actions.ts`; `src/server/auth/native-auth-validation.ts`; `src/server/bootstrap.ts`; `src/server/security/rate-limit.ts`.
- `POST /api/auth/native/refresh` — Validates and rate-limits a native refresh-token request, returning refreshed session material when the configured provider supports it. Files: `src/app/api/auth/native/refresh/route.ts`; `src/server/auth/actions.ts`; `src/server/auth/native-refresh-rate-limit.ts`; `src/server/security/rate-limit.ts`.
- `GET /api/auth/options` — Returns the configured auth UI/provider options with no-store caching. Files: `src/app/api/auth/options/route.ts`; `src/server/auth/actions.ts`.
- `POST /api/auth/reset-password` — Validates a reset token and new password, with independent IP/token rate limits, then delegates the password update to the auth provider. Files: `src/app/api/auth/reset-password/route.ts`; `src/server/auth/actions.ts`; `src/server/security/rate-limit.ts`.
- `GET /api/auth/session` — Returns the current session/auth diagnostic view with no-store headers and request rate limiting. Files: `src/app/api/auth/session/route.ts`; `src/server/auth/session.ts`; `src/server/auth/auth-debug.ts`; `src/server/config/index.ts`; `src/server/security/rate-limit.ts`.
- `POST /api/auth/sign-in` — Authenticates email/password credentials and returns the provider result, applying IP, email, and combined rate limits. When the password is correct but the email is unverified, it answers 403 with `pendingEmailVerification` and a short-lived signed `verificationTicket` for `POST /api/auth/verify-email`. Files: `src/app/api/auth/sign-in/route.ts`; `src/server/auth/actions.ts`; `src/server/security/rate-limit.ts`.
- `POST /api/auth/sign-out` — Clears the current Overlay session cookie. Files: `src/app/api/auth/sign-out/route.ts`; `src/server/auth/session.ts`.
- `POST /api/auth/sign-up` — Creates a password-based account through the configured auth provider with abuse-rate limiting. Files: `src/app/api/auth/sign-up/route.ts`; `src/server/auth/actions.ts`; `src/server/security/rate-limit.ts`.
- `GET /api/auth/sso/[provider]` — Starts the configured SSO provider flow and redirects the browser to the provider authorization endpoint. Files: `src/app/api/auth/sso/[provider]/route.ts`; `src/server/auth/actions.ts`; `src/server/capabilities.ts`.
- `POST /api/auth/verify-email` — Validates an email-verification token and delegates verification to the configured auth provider with rate limiting. Files: `src/app/api/auth/verify-email/route.ts`; `src/server/auth/actions.ts`; `src/server/security/rate-limit.ts`.
- `GET, POST, PATCH, PUT, DELETE /api/better-auth/[...all]` — Catch-all Better Auth transport adapter for the provider’s own authentication endpoints. Files: `src/app/api/better-auth/[...all]/route.ts`; `src/server/auth/better-auth.ts`.

## Bug reports

- `POST /api/bug-report/upload`: Prepares create-only direct uploads for at most 10 supported attachments and 5 MB total. Requires a same-origin browser session, IP/user rate limits and report configuration. Returns a signed user-bound manifest that expires after 10 minutes. File: `src/app/api/bug-report/upload/route.ts`.
- `POST /api/bug-report`: Verifies the browser session, origin, rate limits, idempotency key, description and signed attachment manifest before checking stored size/type, creating a public GitHub issue and notifying the configured owner through Resend. Missing configuration fails closed; an email failure does not retry issue creation. File: `src/app/api/bug-report/route.ts`.
- `GET /api/bug-report/attachment/[id]/[file]`: Verifies the signed object path and stored object before redirecting to a short-lived download URL. Links are public bearer links disclosed in the report dialog, with no-store and no-referrer headers. File: `src/app/api/bug-report/attachment/[id]/[file]/route.ts`.

## 2. Billing, subscriptions, releases, and billing webhooks

Workspace checkout, top-up and portal return URLs include the initiating workspace in `/app/w/<workspaceId>/settings`; changing the active workspace in another tab cannot redirect payment verification to another wallet.

- `POST /api/checkout` — Retired: an account is never free or paid, so after billing capability, session and rate-limit checks it answers `410 account_plans_retired` ("Plans and credit belong to workspaces now"). Workspace plans start at `POST /api/v1/workspaces/[workspaceId]/billing/checkout`. Files: `src/app/api/checkout/route.ts`; `src/server/billing/http.ts` (`accountPlansRetiredResponse`).
- `POST /api/checkout/verify` — Retired: an account cannot be paid, so it answers `410 account_plans_retired` to a signed-in caller (401 otherwise). Files: `src/app/api/checkout/verify/route.ts`; `src/server/billing/http.ts`.
- `GET /api/entitlements` — Returns the authenticated user’s effective billing entitlements, including workspace-aware payer resolution where enabled. Files: `src/app/api/entitlements/route.ts`; `src/server/billing/http.ts`; `src/server/billing/BillingCustomerService.ts`; `src/server/auth/session.ts`.
- `POST /api/portal` — Retired: an account has no plan to manage (a workspace's portal opens from Workspace → Billing), so it answers `410 account_plans_retired` to a signed-in caller (401 otherwise). Files: `src/app/api/portal/route.ts`; `src/server/billing/http.ts`.
- `GET /api/subscription` — Returns the authenticated user’s personal subscription view and rejects attempts to query another user. Files: `src/app/api/subscription/route.ts`; `src/server/billing/http.ts`; `src/server/billing/BillingCustomerService.ts`; `src/server/auth/session.ts`; `src/server/capabilities.ts`.
- `GET, POST /api/subscription/settings` — GET returns the account's billing settings (always free, no automatic top-ups), reporting `planKind: 'paid'` when the person is working in a paid workspace; POST keeps its confirmation and same-origin checks and then answers `410 account_plans_retired`. Files: `src/app/api/subscription/settings/route.ts`; `src/server/billing/BillingCustomerService.ts`.
- `POST /api/topups/checkout` — Retired: after authentication and rate limits it answers `410 account_plans_retired`; credit is added to a workspace at `POST /api/v1/workspaces/[workspaceId]/billing/top-ups`. Files: `src/app/api/topups/checkout/route.ts`; `src/server/billing/http.ts`.
- `GET /api/topups/history` — Returns an empty list: an account has no top-ups of its own (credit belongs to workspaces). Files: `src/app/api/topups/history/route.ts`.
- `POST /api/topups/verify` — Retired: an account has no credit to top up, so it answers `410 account_plans_retired` to a signed-in caller (401 otherwise). Files: `src/app/api/topups/verify/route.ts`; `src/server/billing/http.ts`.
- `DELETE, GET, OPTIONS, POST /api/mcp` — Overlay's MCP server for outside AI apps (ChatGPT, Claude, Cursor, local agents): stateless MCP Streamable HTTP with JSON responses. Auth is an OAuth access token or personal token (`ovmcu_…`, HMAC-signed, resolved to a revocable `mcpGrants` row on every request, so revoking a connection or leaving the workspace ends it). A 401 carries a `resource_metadata` challenge. The tool set is the grant's access level (read, write, everything) run through the same tool pipeline, policy, and entitlements as an Overlay agent, acting as the person; computer, agent-editing, and conversation-bound tools are never offered. Rate limited per grant. Files: `src/app/api/mcp/route.ts`; `src/server/mcp/overlay-mcp-server.ts`; `src/server/mcp/external-mcp-tools.ts`; `src/server/mcp/mcp-jsonrpc.ts`.
- `GET, OPTIONS, POST /api/oauth/register` — Dynamic client registration (RFC 7591) for AI apps: validates redirect URIs (https, localhost http, or an app scheme) and returns a stateless signed client id. Per-IP limit is a loose backstop because hosted apps share egress IPs. Files: `src/app/api/oauth/register/route.ts`; `src/server/mcp/oauth-endpoints.ts`; `src/server/mcp/McpAccessService.ts`.
- `GET, OPTIONS, POST /api/oauth/token` — OAuth token endpoint for the MCP server: authorization code with PKCE S256 (single use, bound to client, redirect, and verifier; a replayed code revokes the grant it made) and rotating refresh tokens (a replayed refresh token revokes the grant). Files: `src/app/api/oauth/token/route.ts`; `src/server/mcp/oauth-endpoints.ts`; `src/server/mcp/McpAccessService.ts`.
- `GET /api/latest-release` — Returns the latest official desktop release metadata when official downloads are enabled; otherwise it returns the frozen/disabled response. Files: `src/app/api/latest-release/route.ts`; `src/shared/web/latest-release.ts`; `src/server/releases/desktop-download-policy.ts`.
- `GET /api/latest-release/download` — Resolves the latest official desktop download metadata/redirect when official downloads are enabled. Files: `src/app/api/latest-release/download/route.ts`; `src/shared/web/latest-release.ts`; `src/server/releases/desktop-download-policy.ts`.

## 5. Connected agents, environments, hosts, and remote artifacts

- `POST /api/v1/harness/continuation` — Internal callback authenticated by `INTERNAL_API_SECRET`; reads the protected, generation-fenced continuation launch and starts the persisted native or personal Harness workflow on the receiving BFF deployment. Duplicate callbacks are idempotent; only the generation owner may execute. Files: `src/app/api/v1/harness/continuation/route.ts`; `convex/harness/continuations.ts`; `src/server/harness/harness-continuations.ts`.
- `GET /api/v1/agent-environments` — Lists the authenticated workspace’s connected agent environments; an environment stored as online is presented as offline after 45 seconds without a heartbeat. Files: `src/app/api/v1/agent-environments/route.ts`; `src/server/app-api/v1/agent-environments/route.ts`; `src/server/app-api/v1/agent-environments/shared.ts`; `src/server/agents/ConnectedAgentControlPlaneService.ts`.
- `POST /api/v1/agent-environments/enrollment-sessions` — Creates a short-lived browser enrollment session and returns the one-time host enrollment command pinned to Node 24 and the exact Agent Host package; the code is not persisted in raw form. Files: `src/app/api/v1/agent-environments/enrollment-sessions/route.ts`; `src/server/app-api/v1/agent-environments/enrollment-sessions/route.ts`; `src/server/agents/agent-enrollment-command.ts`; `src/server/app-api/v1/agent-environments/shared.ts`.

- `POST /api/v1/agent-environments/[environmentId]/drive-credentials` — Device-signed host request (`agent:drive-credentials`, advertised drive v1 required), default off. Issues or renews a bearer for the exact active run/session/execution; persisted state determines actor, binding and personal/workspace scope. Local/VPS bindings require opt-in. Credentials last at most one hour and never exceed the run deadline. Responses are private and never cached. Files: `src/app/api/v1/agent-environments/[environmentId]/drive-credentials/route.ts`; `src/server/app-api/v1/agent-environments/[environmentId]/drive-credentials/route.ts`; `src/server/agents/AgentDriveCredentialService.ts`; `convex/agents/agentDrive.ts`.
