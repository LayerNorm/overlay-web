description: "Validate competing schedulers, worker recovery, signed webhook delivery, dead-letter redrive, and Daytona reconciliation on AWS."
---

Rehearsal 6 validates P6 on AWS. It must use the same immutable release image
for the web app, scheduler, and workers. A local or Neon contract pass is a
prerequisite, not a substitute for this distributed rehearsal.

## Required Topology

- One ALB-backed web service with at least two tasks.
- One scheduler ECS service with desired count `2` and worker mode `scheduler`.
- One worker ECS service with desired count at least `2` and worker mode `worker`.
- RDS PostgreSQL or Aurora PostgreSQL using its writer endpoint.
- ElastiCache Redis with fail-closed rate limiting.
- CloudWatch logs for web, scheduler, and worker services.
- A disposable HTTPS webhook receiver that can return `200`, `429`, `500`,
  timeout, and redirect responses on demand.

Use a disposable database and receiver. Never point the destructive contracts
at production data.

## Environment

```bash
export OVERLAY_DATABASE_URL='postgresql://...rds.amazonaws.com/overlay_rehearsal'
export OVERLAY_DATABASE_SSL_MODE=verify-full
export OVERLAY_BACKGROUND_RUNTIME_ENABLED=true
export INTERNAL_SERVICE_AUTH_SECRET='distinct-strong-service-secret'
export OVERLAY_PROVIDER_DATABASE=postgres
export OVERLAY_PROVIDER_RATE_LIMIT=redis
export OVERLAY_REDIS_URL='rediss://...cache.amazonaws.com:6379'
export OVERLAY_REDIS_FAILURE_MODE=deny
export AUTOMATIONS_ENABLED=true
export WEBHOOKS_ENABLED=true
```

Run the automated database gate from the rehearsal task or a one-off ECS task:

```bash
npm run aws:rehearsal:6
```

The command migrates the disposable database, runs real Postgres P6 contracts,
then validates the AWS endpoint, TLS mode, schema, required schedules, durable
job state, automation attempts, and webhook deliveries.

Run the real Convex side of the shared contract separately before declaring
provider parity:

```bash
npm run test:p6:contracts:convex
```

## Fault Matrix

1. Create enabled interval, daily, weekly, and monthly automations. Confirm the
   UI lists the same schedules after refresh.
2. With both scheduler tasks running, force one occurrence due. Confirm one
   logical run and one durable execution job, not one per scheduler.
3. Exercise both `skip` and `queue` concurrency policies with a deliberately
   slow automation.
4. Stop the worker that owns a running automation. Wait past its lease, start a
   replacement, and confirm one terminal run with an auditable recovered
   attempt.
5. Cancel a queued run and retry a failed/dead-letter run from the UI. Refresh
   and confirm state remains durable.
6. Create a webhook, store the one-time secret, rotate it, and verify the old
   secret no longer validates new deliveries.
7. Drive receiver responses `200`, `429`, `500`, timeout, and redirect. Confirm
   success, exponential retry, timeout recovery, and redirect rejection.
8. Let a delivery exhaust attempts. Redrive it after repairing the receiver and
   confirm the redrive is a new delivery record while old attempts remain.
9. Submit webhook URLs resolving to loopback, link-local, RFC1918, and a public
   URL that redirects private. Confirm creation or delivery fails closed.
10. Attempt automation, run, webhook, delivery, cancel, retry, rotate, and
    redrive operations from another account/project. Confirm no data leaks or
    mutation succeeds.
11. Replace a scheduler task during a tick. Confirm deterministic schedule
    dedupe prevents a duplicate occurrence.
12. Trigger an RDS Multi-AZ failover during queued and running jobs. Confirm
    clients reconnect, expired leases recover, and no completed side effect is
    duplicated.
13. Terminate a Daytona reconciliation worker after lease acquisition. Confirm
    replacement recovery and owner-label enforcement.

## Alarms And Evidence

Create and trigger alarms for:

- Oldest queued job age above the pilot SLO.
- Any dead-letter durable job.
- Worker and scheduler ECS desired/running count mismatch.
- No scheduler `runtime_health` log within two intervals.
- RDS connections, CPU, storage, failover, and transaction errors.
- Webhook dead-letter count above zero.

Capture:

- ECS task definitions and image digest.
- Desired/running counts for all three services.
- CloudWatch logs spanning every fault.
- Database queries showing one logical scheduled occurrence.
- Webhook signature verification and replay rejection evidence.
- Cross-user/project denial evidence.
- Browser and server network evidence showing zero Convex traffic in Postgres
  mode.
- Final `npm run aws:rehearsal:6` JSON output.

P6 passes only when every fault is resolved or documented as an explicit pilot
exception with an owner and deadline.
