# AWS Rehearsal 9 - integrations and Executor

## Topology

Deploy at least two Overlay web tasks and the existing worker fleet. Deploy one Executor task in a separate ECS service. Mount EFS at `/data`, expose the Executor browser console through HTTPS, and restrict its `/api` and `/mcp` paths to Overlay tasks and approved operators. Store the Executor API key, Better Auth secret, and encryption key in Secrets Manager.

## Rehearsal profiles

Run two Overlay releases from the same image:

1. `OVERLAY_PROVIDER_INTEGRATIONS=composio` with a test Composio tenant.
2. `OVERLAY_PROVIDER_INTEGRATIONS=executor` with the self-hosted service.

The UI, `/api/v1/integrations` response shape, chat transcript, and tool-call presentation must remain provider neutral.

## Gates

1. Confirm `/api/v1/integrations?action=health` reports the selected provider and healthy state.
2. Search Gmail, Slack, Notion, one OpenAPI integration, one GraphQL integration, and one MCP integration.
3. Configure a tenant connection, refresh Overlay, open a second tab, and verify consistent connected state.
4. Execute read and write tools. Verify denied tools stay denied and approval-gated tools pause rather than auto-approve.
5. Disconnect an unshared Composio test connection through Overlay. For Executor, confirm Overlay labels the connection as externally managed, rejects an app-side disconnect, then remove it in the Executor console and verify Overlay refreshes to the disconnected state.
6. Delete an Overlay user. Verify Composio user credentials are removed, while Executor org credentials remain intact and are audit-visible.
7. Switch providers without changing frontend code or API consumers. Compare the normalized catalog and tool-call DTOs.
8. Stop Executor during a tool call. Overlay must fail safely, preserve chat state, emit a sanitized error, and recover after service restart.
9. Rotate `EXECUTOR_API_KEY`; overlap old/new keys only for the planned window, then prove the old key is rejected.
10. Restart the Executor task and remount EFS. Prove catalog, credentials, policies, and encryption keys survive.
11. Restore `/data` into an isolated task and verify a known connection and policy without contacting production services.
12. Confirm CloudWatch logs and Overlay audit search contain provider, action, resource, outcome, and duration but no credential values or raw authorization headers.
13. Capture VPC flow logs during the run. Prove no unintended Convex traffic and no unapproved Executor private-network egress.

## Failure gates

Do not certify the release if Executor runs more than one SQLite writer, `/data` is ephemeral, `/api` is public without service authentication, a shared org connection is deleted by one user's account deletion, approvals are bypassed, secrets appear in logs, or provider switching changes app-facing DTOs.

## Required evidence

Attach ECS task definitions, target-group health, EFS mount evidence, Secrets Manager references, normalized API samples for both providers, successful and denied tool traces, account-deletion evidence, key-rotation evidence, restore evidence, CloudWatch screenshots, and VPC flow-log queries.
