title: "AWS Rehearsal 7: Usage, Billing, API Keys, And Administration"
description: "Certify budget concurrency, Stripe and institution profiles, API-key replacement behavior, audit ownership, and administrative controls on AWS."
---

Rehearsal 7 runs the complete P7 gate twice against the same immutable image:
once with Stripe test mode and once with institution-managed billing disabled.
Both profiles use Postgres app data and Redis rate limiting. A local or Neon
contract pass is a prerequisite, not a replacement for distributed failure QA.

## Required topology

- ALB-backed web service with at least two healthy tasks.
- Worker service with at least two healthy tasks.
- Scheduler service from Rehearsal 6.
- Disposable RDS PostgreSQL or Aurora PostgreSQL writer endpoint.
- ElastiCache Redis over TLS with fail-closed rate limiting.
- Stripe test-mode account and a disposable webhook endpoint for the Stripe profile.
- A second deployment profile with `BILLING_PROVIDER=none` and an administrator-managed budget.
- CloudWatch logs and alarms for every service and dependency.

Use disposable databases or restored rehearsal snapshots. The contracts create
and delete users, reservations, billing records, API keys, and audit events.

```bash
export P7_REHEARSAL_WEB_TASK_COUNT=2
export P7_REHEARSAL_WORKER_TASK_COUNT=2
```

For the Stripe profile:

```bash
export P7_REHEARSAL_PROFILE=stripe
export BILLING_PROVIDER=stripe
export DEV_STRIPE_SECRET_KEY='sk_test_...'
export DEV_STRIPE_WEBHOOK_SECRET='whsec_...'
npm run aws:rehearsal:7 | tee evidence/p7-stripe-readiness.json
```

For the institution profile, configure a positive grant for the test user first:

```bash
export P7_REHEARSAL_PROFILE=institution
export BILLING_PROVIDER=none
export P7_INSTITUTION_BUDGET_USER_ID='institution-rehearsal-user-id'
npm run aws:rehearsal:7 | tee evidence/p7-institution-readiness.json
```

The readiness command checks the AWS endpoint classes, TLS, two-task
declarations, live ElastiCache atomic operations, schema compatibility, active
administrators, reservation state, provider-event state, API-key state, audit
state, and the institution budget.

Run the real Convex side of the same behavioral contract before declaring
provider parity:

```bash
npm run test:p7g:convex
```

## Distributed fault matrix

1. Submit 20 simultaneous reservations against exactly ten units of remaining
   budget. Exactly ten succeed and the account never goes negative.
2. Stop the worker after provider work starts but before finalization. Confirm
   the reservation becomes `reconcile_required`, a replacement worker finalizes
   it once, and retrying finalization is a no-op.
3. Trigger an RDS Multi-AZ failover during reservation traffic. Confirm failed
   transactions roll back, pools reconnect, and retries do not double reserve.
4. Replace one web task after an API key is used. Confirm another task accepts
   the key, then immediately rejects it after revoke or rotate.
5. Replace ElastiCache while API-key requests and budget reservations are in
   flight. Confirm rate limiting fails closed and returns to normal after Redis
   recovery without weakening key authorization.
6. Deliver duplicate Stripe events and a pending event after a succeeded event.
   Confirm one grant, immutable succeeded state, payload-hash mismatch rejection,
   and auditable retry attempts.
7. Stop the Stripe worker after event reservation. Confirm failed state is
   reacquired with an incremented attempt and processed exactly once.
8. Exercise subscription create, update, cancel, past-due, and recovery plus
   manual and automatic top-ups in Stripe test mode.
9. In the institution profile, keep Stripe credentials absent. Grant, reduce,
   exhaust, and replenish a managed budget through the admin console.
10. Create, copy, use, expire, revoke, and rotate API keys. Verify every scope,
    cross-user denial, second-tab refresh, and replacement-task consistency.
11. Verify administrators, auditors, billing administrators, support users, and
    ordinary users can perform only their assigned operations.
12. Search audit events by actor, action, and resource. Confirm secret metadata
    is redacted and cross-user data is not returned.
13. Delete a project and account containing usage, billing, API-key, and audit
    state. Confirm owned rows are gone and retained compliance events are
    anonymized where required.
14. Run the authenticated browser matrix for both profiles and capture zero
    Convex HTTP or WebSocket traffic:

```bash
P7_UI_QA_URL='https://profile.example.com' \
P7_UI_QA_STORAGE_STATE='evidence/admin-storage-state.json' \
P7_UI_QA_PROFILE='institution' \
P7_UI_QA_EXPECT_ADMIN=1 \
npm run test:p7g:ui
```

Repeat with `P7_UI_QA_PROFILE=stripe` against the Stripe service. Also run once
as an ordinary user with `P7_UI_QA_EXPECT_ADMIN=0` to prove denial.

## Evidence and pass gate

Capture ECS image digests and task counts, ALB target health, CloudWatch logs,
RDS failover events, Redis replacement events, Stripe event IDs, SQL snapshots,
browser traces, audit searches, and both readiness JSON outputs. P7 passes only
when both profiles pass every automated contract and distributed fault, zero
Convex browser traffic is observed in Postgres mode, and all alarms recover.
