# Changelog

This file records user-visible and operational changes that reach `main`. Pull requests add concise entries under **Unreleased**; the integration agent moves shipped entries into dated sections when cutting a release. Pull requests and Git history remain the detailed implementation record.

## Unreleased

- Open agent destinations before resolving their main thread, with late-result guards that preserve newer navigation. Separate chat directory subscriptions from active transcript/execution updates so streaming does not notify sidebar and archived-list consumers unnecessarily.

- Fix a cancelled ChatGPT/Codex sign-in staying in the provider list. Removing a subscription connection failed with "Subscription cleanup is pending" when a sign-in check was still running, so the connection was never deleted. That check now hands its lock back as soon as it sees the removal, and removal waits for it (at most a minute) before deleting the stored sign-in data and the connection. This changes Convex subscription mutations.
- Let people cancel the ChatGPT/Codex sign-in dialog even when cleaning up the pending sign-in fails. Cancel used to show "Could not cancel this connection. Try again before closing." and keep the dialog open; it now closes at once and removes the pending sign-in in the background (fixes #454).
- Stop shutting down a computer that is being used just because its two-hour session ran out. A long build, an open terminal session or an agent run on a computer used to be stopped about two hours after the last computer action, even while it was busy. The session now keeps extending while the computer is in use (recent activity, an open action or a live run), and a computer stops on its own only when it is idle or the workspace budget is under 2%. A deadline a person sets on an agent task can now be longer than 7 days (the 30-second minimum stays). Docs no longer describe a "24-hour hard cap" on machines.
- Remove arbitrary limits that refused, stopped, cut short or degraded real work; the workspace budget (stop under 2% left) stays the only automatic spending limit. Agents now work in the model's whole context window instead of 32,000 tokens (200,000 when the catalog does not know the model) and get 32,000 output tokens by default instead of 8,192. A very large step no longer fails the run: its stored copy is shortened to fit Convex and the full step stays in file storage. Runs are no longer paused as "stuck" after six segments without visible progress (the recovery hint stays). Automation runs are no longer failed after 15 minutes; only a run that never started within 24 hours expires. Subscription connections accept images (other files are still replaced with a note) and requests up to 32 MiB instead of 2 MB; the subscription bridge changed to match. MCP tool results are shortened past 400,000 characters instead of 50,000. Agents asking agents: the 500,000-token chain limit is gone, and the limits are 50 questions and 50 posts per turn, 200 of each per person's message, 10 hops and 20 mentions. Sub-agents: 16 at once and 5 levels deep instead of 3 and 2. Connected agents: paid runs are no longer stopped after 24 hours (a 30-day credential deadline remains), a machine has 15 minutes instead of 2 to pick up a turn, one message can start 20 agents instead of 5, and each room message keeps 50,000 characters of context instead of 2,000 (the whole context is still bounded by the 128 KiB start-command size installed hosts accept). Earlier tool outputs read back by a model keep 20,000 characters instead of 1,000. Chat attachments allow 500 uploads an hour per person (1,000 per IP) instead of 20 (40). The notebook agent can take 200 steps instead of 20. The daily caps on memory extraction (120) and indexing (200 chunks, 5 MB) are gone; that work is charged to the workspace budget. Kept: security and abuse limits, cycle checks, per-file storage limits, provider hard limits, explicit deadlines and spend limits people set, and free-plan connected-agent limits.
- Make the workspace budget the only automatic spending limit. Overlay no longer estimates, quotes or holds money before a paid call: chat, agents, automations, tools, images, videos, transcription, embeddings, memory work and computers now check the real balance first and charge the actual cost after each call (images and videos when delivered; a cancelled connected-agent run is charged the tokens it used). Work is refused, or stops after its current step, only when the workspace has less than 2% of its budget left and one automatic top-up attempt cannot bring it back. Removed with the estimates: the image "known context limit" refusal, the $0.05 web search hold, the 10-minute computer hold, the $1 computer floor and $15 per-run cap, the per-task spend limit, the "grant more spend" card and its `POST /api/v1/conversations/run/resources` endpoint, and the pause for funding. Admin spend limits per member or agent, explicit deadlines and rate limits still apply. Charges use the cost known at the time (provider receipt or catalog price); the later exact-cost correction is gone. Paused runs from before can only be cancelled.
- Delete the hold machinery behind the old estimates (reserve/finalize/release, the expiry and stale-hold sweeps, the reconciliation queue and its audit script, the released-cost recorder, the margin report and sandbox settlement markers) and add a one-time Convex migration, `billing/retireHolds:releaseRetiredHoldsInternal`, that releases every hold still open, so that money is available again. It charges nothing, is safe to rerun and also clears old machine-lease holds. The `budgetReservations` table keeps its history until a later change removes it.

- Fix long answers that restarted after running out of output tokens. When one model call hit its output cap, the next call never saw the text it had already written: the agent framework (`@ai-sdk/workflow`) drops a cut-off response from its conversation history, and the harness's working state carried only the response's first 8,000 characters. The model resumed from the end of that excerpt, so a 160-item list cut near item 117 continued with "I'll continue… starting from item 17" and later calls restarted the list. The harness now adds the cut-off response back as the last assistant message, records where it really ends in the working state instead of its opening, and asks the next call to continue from the exact character where it stopped with no preamble. A regression test covers a long cut-off list.
- Raise how much one model call can write in personal chat and workspace agents. Every harness call was capped at 8,000 tokens because the limit was taken as a quarter of the 32,000-token working-context budget. Reasoning models such as Claude Sonnet 5.5 count their thinking against that same limit and could use all of it on thinking, writing no text while the run kept continuing. Calls now request 32,000 tokens. Compaction keeps its working-budget reserve, and the reply is bounded only by the model's own maximum and context window. Longer replies still continue in the next call. Each call reserves more spend up front, and whatever it doesn't use is released when the call settles. If a call still uses its whole limit on thinking and writes nothing, the next call now runs with thinking off so it produces the answer, instead of every continuation starting to think again from scratch. Adds tests for the new limits and the thinking fallback.

### Fixed

- Managed sandboxes no longer burn provider budget while idle. Vercel sandboxes have no native idle-stop — they run until the 24-hour `timeout` — so every managed lease provisioned ~96 GB-hours/day of memory whether or not the agent was used. The meter now enforces the lease's idle window itself: a sandbox with no acquire/settle activity for `idleTimeoutMs` (15 minutes) is stopped while the lease stays resumable, turn-slice acquires heartbeat `usage.lastActiveAt` so working sandboxes never cool mid-turn, and `running` leases past their 24-hour `reservedUntil` are reaped instead of lingering forever.

- The reconciliation sweep no longer emits recurring `offline_environment` warnings for managed (`overlay_cloud`) environments. Genuinely stale BYO environments still alert.

### Changed

- Managed sandbox billing now meters the lease, not the turn. Agent-environment turns previously reserved a worst-case 24-hour sandbox cost (~$15) at dispatch, which declined turns outright on wallets that could have run for hours. `ManagedAgentSandboxBilling.reserve` now takes only a ~$1.50 bootstrap hold (low-balance floor plus a short coverage window), and a per-lease meter debits actual provider usage once a minute: each tick reads `instance.usage()`, diffs it against a cursor persisted on the lease (`usage.meteredUsage`/`meterVersion`), and commits the charge plus cursor atomically so retried or concurrent ticks can never double-charge. When the payer's remaining balance falls under $1 (`OVERLAY_SANDBOX_LOW_BALANCE_CUTOFF_CENTS`) or a tick debit is declined, the lease flips to `stopping`, in-flight commands and queued/running turns are cancelled with a `usage_limited` terminal error, and the provider sandbox is deleted by a reaper pass that also retries `cleanup_failed` leases with backoff — closing the gap where `stopping` leases were never reaped. Turn settle is now just the final meter tick plus bootstrap-hold release, and the missing `agentSandboxSettlements` marker on managed-harness settles logs at info instead of throwing `MANAGED_SANDBOX_SETTLEMENT_MARKER_MISSING` into reconciliation. The meter runs from the BFF `agent-environments/operations/reconcile` route (already called by the Convex cron) and the Postgres `app-data.maintenance` job; `OVERLAY_SANDBOX_METER_DISABLED=true` disables it. Provider usage reads never resume an idle-stopped sandbox (`reconnect(reference, {resume:false})` on every runtime adapter), and because providers such as Vercel publish cumulative counters only once a session stops, a running sandbox bills the elapsed window against a virtual wall-time cursor while reap/reset paths stop the instance, take one final meter read, then delete — so session usage is captured rather than lost at teardown. The 24-hour runtime hard limit, free-tier shape (30-minute cap, zero egress), and the standalone sandbox route's worst-case reservation are unchanged.

The environment lease stays `running` after reset while its provider reference names a destroyed sandbox; `ManagedAgentSandboxBilling.reserve` reconnected to it unconditionally, so every subsequent turn died at dispatch ("could not start this turn") before the workflow's recreate step could run. `reserve` now treats an unreachable sandbox as a zero-usage baseline (a recreated sandbox bills its full lifetime), and `settle` resolves the lease's *current* provider reference — the acquire step repoints the same lease when it recreates the sandbox. - Agent saves no longer wedge on a failed computer provision. A `POST /boxes` flake left the bound row in `error` status with no provider ref, after which *any* save that touched the computer — including turning the toggle **off** — died on a 409 ("still provisioning") because `destroy` required a live machine ref. `destroy` now tolerates ref-less rows and treats provider cleanup as best-effort, provisioning retries the provider create once before erroring, and `provision` reclaims a dead `error`/stale-`provisioning` row (machine included) instead of stacking a duplicate on the owner binding — so retrying a failed computer setup actually provisions on the next save instead of failing forever.
