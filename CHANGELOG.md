# Changelog

This file records user-visible and operational changes that reach `main`. Pull requests add concise entries under **Unreleased**; the integration agent moves shipped entries into dated sections when cutting a release. Pull requests and Git history remain the detailed implementation record.

## Unreleased

### Added

- **Fixed: teammates could search other people's personal chats and DMs.** Every chat message was indexed as visible to the whole workspace, so in a workspace with more than one person `search_messages` and `search_knowledge` could return text from someone else's personal chat or a DM they were not in. Only public-channel messages are shared now; personal chats, DMs, and private channels stay with their author, and retrieval re-checks each foreign message against its conversation so nothing indexed under the old rule can leak while it waits to be re-stamped. Existing message chunks were re-stamped (no re-embedding). Search inside a DM now finds your own messages, not the other person's (you can still open the chat). See `docs/plans/TOOL_SCOPING_PLAN.md`.
- **Workspaces stop looking special (Workspace scoping, Phase 5a).** Every workspace now has a name that says whose it is ("Maya’s workspace"), not "Personal": the 249 existing first workspaces that still had a stand-in name were renamed, and new people name their workspace before the tour. Owners and admins can rename any workspace from Workspace settings (new `PATCH /api/v1/workspaces/{id}/lifecycle`). One avatar and one "N members" label for every workspace. Billing is unchanged; workspace-level billing (5b) and a plan for scoping tools and search (`docs/plans/TOOL_SCOPING_PLAN.md`) are written up for approval.
- **Workspace connectors, Move/Archive everywhere, and tidier expanded rows (Workspace scoping follow-up).** Extensions → Workspace → Connectors now shows the same connectors, but connecting one links the workspace's own account (shared by every member, separate from personal accounts, unaffected when someone leaves); one per connector, removable by whoever connected it or an owner/admin, and who may connect follows the "anyone can share skills, MCP servers, and connectors" setting. In a workspace, agents get a second connector tool set (`workspace_…`) that acts through those accounts. Not yet exercised with a live OAuth link. Move to Workspace/Personal and Archive are now also in the note editor, the file viewer, and card-layout files and folders. What an expansion reveals (a scope's sub-rows, threads) is no longer indented under its parent; the rule is in `docs/develop/interface-design.md`.
- **Move, archive, and restore from the app; agents use what the workspace shares; usage top-ups follow the workspace setting (Workspace scoping, Phase 4).** Hover a file, note, or automation row, or open a skill or MCP server, to move it between Personal and Workspace or archive it (select several files to do it in bulk); restore from Archived. Buttons appear only where you are allowed, and moves disappear for members when an admin turns moving off. Skills and MCP servers shared with the workspace are available to every member's agents (an MCP server runs with its creator's credentials on Overlay's side; members never receive them). Mentions find shared items. The list tools (`list_notes`, `list_files`, `list_skills`, `list_automations`) take an optional `scope`. Members may add workspace usage only when "Anyone can add usage" is on. Moves and archives are written to the audit log. Archived files now show the right Personal/Workspace tag. Connector sharing is not included yet. See `docs/plans/UNIFIED_SCOPES_PLAN.md`.
- **The prerendered shell's two inline scripts are allowed by hash under the nonce CSP.** With `SECURITY_CSP_NONCE=true`, the static shell shipped two inline scripts with no nonce, which the browser blocked on every `/app/*` load (two console errors): React's `$RT` timer and the theme initializer, so the saved theme was applied only after hydration. Both are now allowed by hash (`INLINE_SCRIPT_HASHES` in `src/proxy.ts`, with tests that fail if React or the theme script changes).
- **One secondary panel for Chats, Files, Extensions, Automations, and Agents: Personal, Workspace, Archived (Workspace scoping, Phase 3).** Each page's side panel now starts with the same three rows; the selected one opens that page's sub-rows beneath it (Files: All/Notes/Files/Outputs; Chats → Workspace: Direct Messages/Channels/Activity; Extensions: Connectors/Skills/MCPs/Apps), followed by New and search, then the list. Your choice follows you between pages and is in the URL as `?scope=`. New is hidden in Archived, says "in workspace" in Workspace, and is hidden for members when an admin has restricted who can create there. Archived shows everything archived from either scope with a Personal/Workspace tag and a restore button. Notes, uploads, skills, MCP servers, and automations are created in the scope you are viewing. Moving and archiving items from the UI arrives in Phase 4. See `docs/plans/UNIFIED_SCOPES_PLAN.md`.
- **Personal and Workspace scopes, and Archive, for files/notes/outputs, skills, MCP servers, connectors, and automations (Workspace scoping, Phase 2; backend only, no visible change yet).** Every one of these can now be Personal (only you, within the workspace) or Workspace (shared with its members), and archived from either. New workspace settings, all defaulting to "anyone in the workspace": who can create or edit workspace skills/MCP servers/connectors, who can create or edit workspace notes/files/outputs/automations, whether members may move items between Personal and Workspace, and who can add usage (stored; enforced later). Only the creator can move an item; owners and admins can edit and archive other people's workspace items but never move them back to Personal. Lists take `?view=personal|workspace|archived`, creates take `scope`, and new `POST /api/v1/scope` moves, archives, or restores. Workspace memories now hide other people's owner-only entries. Existing items are all Personal, so nothing changes for anyone until something is moved. See `docs/plans/UNIFIED_SCOPES_PLAN.md`.
- **Knowledge bases, projects, and the legacy notes/outputs tables are removed (Workspace scoping, Phase 1).** The unused knowledge-base and project tables and every `projectId` field are gone from the schema. Notes and outputs live only in `files`; the 33 live legacy notes and 18 completed outputs that had never been copied were migrated first, so some people will see old notes and outputs reappear in Files. Old note and output ids still resolve. See `docs/plans/UNIFIED_SCOPES_PLAN.md`.
- **UI polish: agent threads, the agent panel, and the people picker.** In the sidebar, an agent's threads and "New thread" now line up under its avatar and name, and the archive and delete buttons on a hovered thread sit on a solid background instead of being hidden by the title. The agent side panel now looks like the new-agent dialog (centered avatar, then Name and Description), with the Config buttons side by side ("From your computer", "Upload folder") instead of stacked. The picker for adding people to a DM or channel shows each agent's own avatar and description instead of a generic icon.

A reply with no tool calls shows all its text. Agents are asked (native agents' system prompt, and a RESPONSE_STYLE line for Claude Code / Codex) to end with a short summary. "Settings → Agent accounts" is now **Settings → Agents**, with a new "Collapse working details in responses" toggle (default on; new `collapseAgentWork` setting) above the Agent accounts list. Actions an agent did not name show as "Tool call" instead of "tool call". Personal chats are unchanged.

Choosing a model such as `gpt-6-luna[high]` made every run fail ("the ACP agent did not advertise that model") because a ChatGPT sign-in offers plain names; the host now applies the name and sets the reasoning level separately.

Providers and Computers now have their own icons in the settings sidebar instead of repeating General's. Info tooltips (the ⓘ in the new-agent dialog and elsewhere) now show above dialogs and menus instead of behind them.

- **A reply placeholder with the agent's avatar appears the moment you send a message to an agent**, instead of nothing for a couple of seconds. The header's "Attach" button and its dialog (which did nothing) are removed.
- **The idle sweep's fallback runs every 10 minutes instead of every minute** (the per-minute pass still meters billing and supervises runs; the event-based idle timer is the primary stop).
- **Agent machines stop exactly 10 minutes after their last run ends.** The idle stop is now event-based: a run's end schedules a check for 10 minutes later (Convex scheduled function, cancelled by any newer message through a token on the lease), which stops the machine unless something happened or a run is going. The per-minute meter pass remains as the fallback: it starts a missing timer and stops a machine whose timer was lost, 2 minutes after the window. "A run is going" is now a real check of the environment's remote runs instead of the run's 24-hour maximum, so a run that never settles no longer keeps a machine up. See `docs/develop/agent-machine-idle.md`.
- **Choose the model of a Claude Code or Codex agent, and connect its account while creating it (Overlay Cloud agents).** The new-agent dialog and the agent page have a Model field: Claude Code (Default, Opus 5.5, Fable 5.1, Sonnet 5, Haiku 4.5) and Codex (GPT-6 and GPT-5.x models, with a Reasoning level), read from the agents themselves. The choice is stored after `byo/<adapter>#` in the agent's `modelId`, sent to the host as `metadata.model`, and applied through ACP `session/set_model`; a model the agent does not offer fails the run with the agent's own message. In the dialog, an agent with no account shows a Connect button (ChatGPT sign-in for Codex) and the account is saved under Settings → Agent accounts. A connected agent's actions now show the title the agent gave them instead of "Remote Action", and its text and actions stay in the order they happened instead of all actions collecting at the bottom. Agent Host 0.3.9, image `overlay-agent-v4`.
- **Cloud agent machines stop after 10 idle minutes (was 15), and the connected-agent run UI is simpler.** A running connected agent is stopped with the Stop button in the message toolbar (it cancels the run); the separate "Cancel run" text button is gone. The second, avatar-less "responding" indicator under the messages is removed, leaving the one with the agent's avatar.

### Fixed

- **Deleting an account now deletes its stored credentials from the vault.** Account deletion removed the Convex rows for model-provider keys but left the secrets in the credential vault, now also true for agent accounts. It lists every vault reference the person stored and deletes each before the rows are removed; if any cannot be deleted, the deletion stops with an error and can be retried, so no secret is orphaned. Needs the new `listCredentialRefsByServer` Convex queries deployed first.
- **Sandbox commands honour their own environment.** The Boat adapter applied only the machine-wide environment and silently dropped a command's `environment`.

### Added

- **Agent Host 0.3.6** (`@layernorm/overlay-agent-host`, `@layernorm/overlay-agent-bridge-protocol`): connected agents receive Overlay's MCP server for workspace tools. New enrollments pin 0.3.6; existing hosts keep working without it and pick up the tools when upgraded.
- **Workspace files in every managed harness sandbox** (since removed with Vercel Sandbox, see Removed): before a hosted Claude Code, Codex, OpenCode, Pi, or Hermes turn, the summoning person's workspace files are mirrored into `./overlay` in the agent's working directory (notes as `.md`). After the turn, files the agent changed or created there are saved back to Overlay. Edits update the original guarded by the mirrored revision, an edit that raced a change in Overlay is saved as an "(agent copy)", and deleting a mirrored file never deletes it in Overlay. The mirror is rebuilt each turn, needs the agent's `read_file` grant (saving back needs `write_file`), and is limited to 2,000 files and 100 MB. `OVERLAY_HARNESS_FILE_SYNC=0` turns it off. The sync runs host-side through the same file and note services as the app, so no storage credentials enter the sandbox.
- **Large text files live in object storage**: text over the Convex document limit (~850 KB) is now stored as one R2 object with a searchable inline prefix (`files.textInObjectStore`), rather than being split into `(part N of M)` rows. `read_file` and `GET /api/v1/files?fileId=…&fullText=true` return the full text. Edits move text between inline and object storage as its size changes. Agents' `write_file` accepts up to 10 MB. The Files editor shows these files read-only, since it only loads the prefix. `list_files` now pages past the list endpoint's 100-row cap.

### Fixed

- **Files and folders created through `/api/v1/files` land in the caller's workspace.** `FileService` received the request's workspace but dropped it on every create path: new folders, text files, R2 uploads, and ingested documents. The rows had no `workspaceId`, so workspace-scoped listings (the Files page, `list_files`) never showed them. Background ingestion now carries the job's workspace too. Rows created before this fix still have no workspace; `migrations/backfillWorkspaceIds` can assign them.

### Added

- **Overlay workspace tools for every harness agent**: hosted harness agents (Claude Code, Codex, OpenCode, Pi, Hermes in an Overlay sandbox) and connected agents on a user's own machine now get the same workspace tools as an Overlay agent with the same grant: notes, files, memory, knowledge search, automations, connected apps, and MCP servers. Hosted harnesses receive them as host-executed tools, so each call runs on Overlay's servers and the sandbox gets no token or extra egress. Connected agents receive an MCP server (`POST /api/agent-mcp`) through the Agent Host, authenticated by a per-run token that stops working when the run ends. It needs a host release (the metadata key is ignored by older hosts). Agents also get file tools (`list_files`, `read_file`, `write_file`, `create_folder`, `move_file`). Reads join the Knowledge group and writes form a new File editing group; revision-guarded writes return 409 on a concurrent change. Grants saved before a group grew now hold the tools that joined it, which also fixes agents created before the patch-style note tools not receiving them. Fixed: every tool call in an agent turn shared one idempotency key, so a second write to the same route in one turn was rejected with 409; keys are now derived per tool call and per request, which keeps replays idempotent.

- **Notes are Markdown, with patch-style agent tools**: notes are stored as GitHub-flavored Markdown with `$…$`/`$$…$$` math. Before, the editor saved TipTap HTML and agents saved Markdown, and the loader guessed the format with a regex. Editor features Markdown can't express (underline, highlight, sub/superscript, alignment, YouTube embeds, merged or sized table cells) are kept as small sanitized inline HTML. One converter, `@overlay/app-core/note-markdown`, serves the editor (Markdown ↔ TipTap HTML at load and save), the server, the share page, and the backfill. `NoteService` stores Markdown even when older desktop clients send HTML, and reads legacy HTML rows as Markdown. Agents get `append_to_note`, `replace_note_section`, and `edit_note` (exact find/replace), so a change no longer means regenerating the whole note. `get_note` returns a `revision` and a heading outline, and every agent write is guarded by the revision it read, so an agent edit can no longer silently overwrite what someone is typing. Note tags are now persisted (Convex `files.tags`), blank note titles are stored as "Untitled", and the share page renders legacy notes, math, and inline formatting. Agent note tools now write through `/api/v1/notes` instead of `/api/v1/files`. Release step: after the Convex deploy, run `npx convex run migrations/notesToMarkdown:run '{"dryRun": true}'` and then without `dryRun` to rewrite stored HTML notes. It's idempotent, keeps `updatedAt`, and skips rows edited mid-run.

- **Several agents per Slack channel**: any number of workspace agents can now be bound to the same Slack channel. ### Changed

- Managed sandbox billing now meters the lease, not the turn. ### Fixed

- Saving an agent on a non-Claude managed runtime (OpenCode, Codex, Pi, Hermes) no longer fails with a bare `Request failed (500)`: the Convex `harness` validator in `collaboration/agents` and the `workspaceAgentDefinitions` schema only accepted `overlay`/`claude-code`, so arg validation rejected every other runtime before the handler ran. The union now covers the full `WORKSPACE_AGENT_HARNESSES` list, and a workspace-policy denial maps to a real 403 instead of an opaque 500. The dev Convex deploy was also unblocked by tolerating legacy/extra fields (`cancelAtPeriodEnd`, external-surface fields, `platforms`) as optional in the schema.
- The create-agent editor shows the runtime picker again for brand-new agents: creation inserts a draft row then opens edit mode, so locking the runtime on edit mode also locked it for never-saved drafts — drafts now keep the picker until first save while real edits stay locked.
- Managed harness turns survive a reset or expired sandbox. The environment lease stays `running` after reset while its provider reference names a destroyed sandbox; `ManagedAgentSandboxBilling.reserve` reconnected to it unconditionally, so every subsequent turn died at dispatch ("could not start this turn") before the workflow's recreate step could run. `reserve` now treats an unreachable sandbox as a zero-usage baseline (a recreated sandbox bills its full lifetime), and `settle` resolves the lease's *current* provider reference — the acquire step repoints the same lease when it recreates the sandbox. Sandbox settlement is also `.catch`-guarded on every path: it previously rethrew inside `finalizeManagedHarnessTurn` after the reply was already persisted, which marked the written message failed (hiding its text) and the run `model_failed`; the reservation's reconcile path now recovers the cents without failing the turn.
- A hosted agent's runtime can no longer be changed after creation. The runtime is the agent's identity — its environment, binding, and sessions are all per-harness — so the editor renders it as a fixed row; switching runtimes means archiving and recreating the agent.
- Agent saves no longer wedge on a failed computer provision. A `POST /boxes` flake left the bound row in `error` status with no provider ref, after which *any* save that touched the computer — including turning the toggle **off** — died on a 409 ("still provisioning") because `destroy` required a live machine ref. `destroy` now tolerates ref-less rows and treats provider cleanup as best-effort, provisioning retries the provider create once before erroring, and `provision` reclaims a dead `error`/stale-`provisioning` row (machine included) instead of stacking a duplicate on the owner binding — so retrying a failed computer setup actually provisions on the next save instead of failing forever. Server logs now record the underlying provider error for 5xx computer failures instead of swallowing it in `cause`.
- Archiving an agent now destroys its bound computer (best-effort): archived agents previously kept their machine — and its row — running and billing with no UI path back to it.
- Scheduled automations actually fire again. The `sleep()`-based per-automation scheduler workflow could not survive deployments (no durable workflow world is configured), so every enabled automation silently stopped running on schedule. Scheduled dispatch is back on the minute cron: `claimDueRuns` inserts a queued run and atomically advances `nextRunAt` (one claim per due slot — a run missed during downtime fires once late, not repeatedly), then each claimed run is dispatched through the same durable one-shot automation workflow as manual runs, with the workflow's own steps settling run status. `POST /api/v1/automations/{id}/start-scheduler` is now a deprecated no-op; the editor no longer calls it, and Postgres deployments keep their own `automation.schedule-due` job. Automations that were already enabled resume on the first cron tick after deploy — no re-saving needed.
- Image attachments in chat no longer fail to send: pasted screenshots and picked images were inlined as raw base64 data URLs inside the message JSON body, so a multi-MB image blew past the platform request-size cap and the send failed outright. Images are now downscaled to a 2048px edge and re-encoded as WebP client-side before attaching (GIFs pass through untouched since canvas encoding flattens animation; originals are kept when re-encoding can't beat them), with per-image and per-message size caps that surface a clear error instead of a failed send.
- Agent computer and agent-management tools no longer fail with `[tools] Tool not allowed` — `computer_exec`/`computer_read_file`/`computer_write_file`/`computer_list_files`/`computer_open_url` and `create_agent`/`update_agent` were exposed by `build.ts` but missing from the global `OVERLAY_TOOL_IDS` registry, so the defense-in-depth assert rejected every call. `COMPUTER_TOOL_IDS` now lives in `@overlay/tools-core` (re-exported by `tool-groups.ts`) so the registry and the agent group share one list, and a test pins every asserted id.
- Personal Chat Work mode no longer dies on tool schemas carrying JSON Schema `format` annotations: the workflow step that compiles tool schemas runs Ajv in strict mode and threw `unknown format "uri"` on tools like `computer_open_url`, failing every Work run that surfaced them. `format` keywords are now stripped when tool schemas are serialized for durable execution (they are advisory and do not constrain model input), and the chat banner now renders the run's real `terminalError` message instead of the generic "The run could not be completed".
- Settled assistant turns no longer hide answer text: the "Worked for N" collapse used to fold everything before the last text segment — including earlier answers — into the collapsed row. Work segments now fold behind one summary row at the top while every text segment keeps rendering in order, so `answer → tool call → closing line` shows both texts uninterrupted.
- Personal Chat Work mode now runs every model provider durably — BYOK keys, OpenRouter, and NVIDIA NIM no longer fail with `Unknown model: …`. The turn was the last `WorkflowAgent` caller: its internal model step resolved `gateway.languageModel(<id>)`, which only knows AI Gateway ids. `personal-chat-work.ts` now runs the same manual durable loop as automation turns — a `streamText` step rebuilds the model via `getLanguageModel` (BYOK credentials read from the vault at call time, never in the workflow log) and forwards live `ModelCallStreamPart`s so token-level streaming to the client is preserved — then one durable step per tool call, with the approval hook unchanged.
- Agent settings on the agents surface now docks as a right side panel (via the shell's `rightPanel` slot) instead of stacking under the conversation; dialog mode remains available as a toggle.
- Agent DM headers and message avatars now track the agent's live directory name — renames in the editor propagate immediately via `agent-directory-changed` instead of showing the stale "Untitled agent" snapshot stored on the conversation/participant records.
- Agent DM message rows now match personal chat: hover no longer paints a row background, and the action row reveals beneath the message instead of a floating rail at the top. Channels keep the Slack-style floating rail.
- Archiving a one-to-one DM no longer asks "for me or for everyone" — there's nobody else to keep it for, so it archives directly from both the conversation menu and the chat list. Channels and group DMs still ask.

- Fixed display-math fences glued to equation lines (`… × 100$$`) reflowing onto their own lines, stray `$` inside display spans repaired, and TeX grouping parens preserved inside single-dollar spans — sloppy model output now degrades to readable math instead of raw code.
- Fixed currency amounts being eaten by math rendering (`$20/mo **— $100…` tables): dollar signs followed by digits are now classified as currency openers and escaped unless the span carries explicit TeX structure, so prices survive KaTeX. Genuine digit-led math (`$2x + 1 = 5$`, finance examples) still renders.
- Fixed currency clauses containing hyphenated words being mangled into italic math (`$1.4M … For SV pre-seed, frame $` rendered "pre-seed" as a subtraction and let KaTeX eat the rest of the sentence): the math-minus heuristic now requires a spaced minus or single-char operands (`x - 1`, `a-b`), so multi-char word hyphens (`pre-seed`, `18-month`, `user-month`) stay prose.
- Fixed display equations clipping their bottom subscripts/descenders in chat and the notes editor: `.katex-display` is a horizontal scroll container whose tight bottom padding clipped glyph ink that overflows the last line box — bottom padding now absorbs it and the vertical axis degrades to a scrollbar instead of an invisible cut.
- The settled-turn collapse row now reads "Worked for {duration}, called N tools" and the duration survives reloads: it is derived from the assistant message's persisted `createdAt`→`updatedAt` span (the row is written `generating` at turn start and patched through settle on both backends), so reloaded agent replies and personal-chat turns show real timing instead of a bare "Worked".
- Message activity notifications no longer fire for a conversation you are actively viewing: the notification fan-out now skips any participant with a fresh online presence session parked on that conversation (the 45s presence heartbeat already reports it), so an agent answer arriving in the DM you have open does not also badge Activity.
- Fenced code blocks no longer render inside a second padded box: react-markdown wraps the block in `<pre>`, which carried its own background/padding around the code-block chrome — the renderer now unwraps `pre` when it directly contains the code block (bare fences keep the plain `pre` styling), preserving the stream-soften animation.
- Custom OpenAI-compatible providers no longer require an API key — the flag gates the dialog's Test/Save buttons, `POST /connections`, `POST /connections/test`, and the runtime gateway, so keyless endpoints can now be connected and used; when no key is stored no `Authorization` header is sent. (Note: OpenCode Zen's `/models` is keyless, but its completions still require an `OPENCODE_API_KEY` — its `*-free` models are session-locked to the OpenCode client.)
- Custom provider connections are easier to tell apart: the dialog's name field moved up under Provider as "Provider name" and auto-fills from the API base URL's host (e.g. `opencode.ai`) until edited, and connection rows show the endpoint host under the name instead of repeating the generic preset label.

- Pinned the Agent Host CLI restart/service hints, README, and launchd test to the released `0.3.5` line (they still pointed at `0.3.4`), and extended the release-gate script to assert all version pins together so the drift cannot recur.
- Fixed Workspace → People showing the authenticated provider user ID instead of the person’s profile name; existing member principals are repaired from the current browser session, and newly created workspaces start with the correct owner name.
- Allowed `data-remote-agent-commands` parts in the conversation message schema and BFF serialization: the Convex validator rejected connected-agent command events with 500s, and the BFF conversation serializer dropped the commands payload, leaving the agent DM slash menu empty after a page load.
- Fixed the agent DM slash menu ignoring typed input: the composer kept its live text outside React state by design, so the slash-menu hook only ever saw programmatically set text — typing `/` did not open the menu, filtering and selection did not update, and choosing a command left the menu stuck open. Typing now refreshes composer state only while a slash token is on screen, preserving the no-re-render-per-keystroke behavior for normal text.
