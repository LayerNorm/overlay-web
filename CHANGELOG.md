# Changelog

This file records user-visible and operational changes that reach `main`. Pull requests add concise entries under **Unreleased**; the integration agent moves shipped entries into dated sections when cutting a release. Pull requests and Git history remain the detailed implementation record.

## Unreleased

- Keep typing responsive while a reply streams. In agent threads and other rooms, every streamed update used to re-render every message in the thread, because the live query returns fresh copies of unchanged messages and each row rebuilt its handlers; unchanged messages now keep their identity and rows skip re-rendering unless something they show changed (their content, status, edit state, reactions, reply count, highlight or turn actions). In personal chat and rooms the message box no longer re-renders on streamed updates; its buttons always call the current action, and it still updates when its own text, attachments, loading state, queue or context meter change. In personal chat, a finished reply no longer re-renders on every streamed update just because the reply in progress started after the page loaded. An agent thread's computer and folder settings now stay the same object between updates, so its footer and + menu don't force the message box to re-render. Adds render counters for the chat view, message list and room transcript, plus counters that name which input caused a message box or finished-reply re-render, documents how to measure typing in agent threads, and adds tests for both the skipped and the still-required re-renders.
- Make common actions respond on click instead of after the server answers. Switching workspaces navigates at once (each workspace address already names its workspace, so saving it as the default happens in the background) and no longer hides the page behind a loading state while a request finishes. Assigning a task shows the new assignee immediately and reverts with an error if the server refuses. The task composer clears on submit so the next task can be typed right away; if creation fails, the task and all its settings remain in a retryable item below without replacing current work. Creating an agent closes the dialog right away, opens the agent as soon as it exists, and provisions its computer afterwards instead of making the dialog wait for it; a refusal reopens the dialog with the draft intact.
- Make streamed replies flow smoothly. Agent replies arrive from the server in bursts of up to 200 characters every quarter second, and chat replies in smaller bursts, which made text jump. The transcript reveals each burst a little at a time on word boundaries and shows the complete final text as soon as streaming ends, catching up at once after a background tab. Group rooms keep following the newest text as it reveals. The 24px chat mark stays visible for the full active response and disappears when it settles. Agent-thread replies also show the 24px Overlay mark below the reply while it is still streaming, as chat replies already did, instead of only moving the avatar's eyes.

- Say when a model provider, not Overlay, stopped an agent task, and log why. - Recover agent turns whose model connection drops mid-response instead of failing them with "A model request ended without confirmed usage. Reconcile the outstanding request before retrying it." That happened when a long single generation (for example writing a whole page into one file) lost its stream before the provider reported usage. Nothing could clear the open call, so the turn always ended and showed the error twice. Now the dropped call is recorded as a failed, zero-usage call (it is not charged) and the harness retries it on the same model, up to three times in a row, so each call is still charged at most once. A provider that omits or sends invalid token counts is treated the same way instead of stopping the run. Real causes are reported first: timeouts, rate limits, provider outages, account and invalid-request errors now show their own message instead of the generic one. A permanent cause such as a rejected key is not retried. When the cause is still unknown after retries, the message now reads "The model connection dropped before the response finished. Send your message again." and appears once, as the error card, not also as the message text. Each failed run logs one `[harness] run failed` line with its diagnostic ID, code, stage and error name, so a diagnostic ID can be found in Vercel logs. Convex must be redeployed with this change because it checks the diagnostic wording.
