# Changelog

This file records user-visible and operational changes that reach `main`. Pull requests add concise entries under **Unreleased**; the integration agent moves shipped entries into dated sections when cutting a release. Pull requests and Git history remain the detailed implementation record.

## Unreleased

### Added

- **Agent threads and nested agent resources**: workspace agents now own multiple chat threads (`conversations.agentId`) that nest under the agent in the sidebar instead of appearing in Chats, plus any automations drafted inside those threads (`automations.agentId`), which disappear from the standalone Automations page and run under the agent's instructions, tools, and environment. The sidebar gains Personal/Workspace/Archived tabs above New agent; expanding an agent lazy-loads its threads and automations. Threads are created via `POST /api/v1/agents/[agentId]/threads` (fresh thread every time — the legacy singleton DM is adopted as the main thread by `POST .../threads/resolve`), archived per-participant via `PATCH .../threads/[threadId]`, and deleted via `DELETE .../threads/[threadId]` — deletion of an agent's last surviving thread is refused (`AGENT_LAST_THREAD`) so an agent always keeps a main thread, derived as the oldest survivor. Archiving an agent preserves its thread participation so the Archived view renders full history; `POST .../restore` re-activates it, and agent-owned automations refuse to run (scheduled or manual) while their agent is archived. One-to-one DMs opened with an agent principal bind to the agent automatically and route to the agents surface. A two-phase migration (`convex/migrations/backfillAgentThreads.ts`, server-secret gated, paginated) stamps `conversations.agentId` on existing agent DMs then `automations.agentId` via `sourceConversationId`.
- **Agent gateway for in-box CLIs (metaharness v1)**: `POST /api/agent-gateway/{anthropic|openai}/v1/*` is a metered model proxy — `computer_exec` injects `ANTHROPIC_BASE_URL`/`OPENAI_BASE_URL` plus a short-lived scoped token (`OVERLAY_AGENT_GATEWAY_SECRET` or `INTERNAL_API_SECRET`) into every command, so agent CLIs inside a box (`claude`, `codex`, `opencode`, `pi`, `hermes`, …) authenticate through Overlay and never see a real provider key. Requests reserve budget before forwarding (real keys resolved from WorkOS Vault `ANTHROPIC_API_KEY`/`OPENAI_API_KEY` with env fallback), SSE streams are tapped for provider-reported token usage, and spend finalizes through the existing reserve/finalize pipeline billed to `agent:<id>`. Unpriced models bill a conservative fallback (`OVERLAY_AGENT_GATEWAY_FALLBACK_USD`) rather than going unmetered.
- **Environment machines unify with computers**: an Overlay Cloud environment's sandbox is now also its bound agent's machine — computer tools (`computer_exec`, file read/write/list, `computer_open_url`) resolve the environment's box when no computer row exists, `POST /api/v1/agent-environments/{id}/desktop` issues a live desktop ticket on it, and Settings → Computers lists environment machines alongside computer rows. Agent creation skips provisioning a second computer when the agent binds to a managed environment.
- **SQL read mirror for self-hosted deployments** (`examples/customer-deployment/mirror/` + `docker-compose.mirror.yml`): a sidecar that streams the supported Data Sync endpoint (`POST /api/v1/data/sync`) and materializes every Convex table as `mirror.<table>(id, creation_time, ts, doc jsonb, synced_at)` in customer-controlled Postgres — the supported relational surface for BI tools and data lakes (never query Convex's internal `documents`/`indexes`). Durable opaque cursor in `mirror._meta` with per-page transactions, so restarts resume and mid-page crashes replay idempotently; `truncates` events `TRUNCATE` mirror tables in-transaction so bulk replaces can't drift it; component tables prefixed (`stripe_*`); nanosecond `ts` preserved losslessly; optional `MIRROR_TABLES` allowlist and `MIRROR_ADMIN_URL` auto-provisioning. Verified live against a deployed stack (115 tables snapshot, live inserts/replaces replicating in seconds). `npm run test:mirror` runs unit + integration suites (integration needs `MIRROR_TEST_DATABASE_URL`).

### Changed

- **Managed HarnessAgents are grandfathered**: `OVERLAY_MANAGED_HARNESS_ROLLOUT_STAGE` now gates *creation* only — turn dispatch uses a separate run gate (feature flag + workspace policy) so existing harness agents keep running with the stage at `off`. `upsertBinding` refuses new (agent, environment) harness pairs when creation is gated but always allows re-saving an existing pair; the picker returns bound harnesses as `legacy: true` entries (404 only when none exist); the editor filters legacy entries out of the create-mode selector and rebinds grandfathered agents on their existing environment instead of dropping the binding on save. The `managedHarnessAgents` feature flag remains the emergency kill switch for the whole surface.
- **Overlay Cloud agent environments default to boat boxes** (`OVERLAY_MANAGED_SANDBOX_PROVIDER` now defaults to `box` when `BOX_API_KEY` is set; `vercel`/`daytona` remain selectable). Persistent agent hosts run on the provider's own dollar-accurate usage accounting — `GET /boxes/{id}/usage` returns multiplier-adjusted billable seconds and list-price `dollars`, which the lease meter debits as deltas (provider-reported spend wins over the seconds rate card; the card is only a fallback when the endpoint omits dollars, tunable via `OVERLAY_BOX_SECONDS_PER_DOLLAR`). Fleet-level alerting: when any box lease is active, each meter sweep probes `GET /limits` and warns when `canStart` is false or the account's machine-second balance drops under `OVERLAY_BOX_LOW_REMAINING_SECONDS` (2h default). Boxes have no custom-image or egress-allowlist primitives, so hosts bootstrap via `npx @layernorm/overlay-agent-host` (`OVERLAY_AGENT_HOST_PACKAGE`) and run `allow_all` — safe because the box holds nothing sensitive (single-use enrollment code; model keys stay server-side behind the gateway). Harness-mode provisioning still requires an egress-allowlist provider and rejects `box` loudly.
- **Ephemeral sandbox execution is pinned to its own provider** (`OVERLAY_EXEC_SANDBOX_PROVIDER`, default `vercel`) so chat/automation `sandbox.run` calls can never follow the persistent-agent provider to a provider without deny-all egress. The run handler now `stop()`s, reads final usage, finalizes billing, **and deletes the sandbox** in `finally` — a delete failure is logged and swept rather than masking the run result. The reconcile route (already cron-driven every minute) additionally runs an orphan sweep (`ephemeral-sweeper.ts`) that deletes any `overlay-sandbox-*`-prefixed non-persistent Vercel sandbox older than `OVERLAY_EPHEMERAL_SANDBOX_STALE_MS` (15m default), covering sandboxes orphaned by aborted requests; sweep results are reported in the reconcile response.

### Fixed

- **Automations no longer hijack the conversation they were created in**: `sourceConversationId` is now provenance only — never a run target, never hidden from Chats, never deleted with the automation. Every automation executes in its own owned thread (`conversationId`, `isAutomation`), created on first run or on the first message in the automation surface, and every run appends to it. Previously, creating an automation inside a chat/agent thread made runs write into that thread, hid it from Chats, and (for drafts) deleted it with the automation — which also bounced an open view back to the chat list. Automation-run messages now carry the automation's name as the author instead of "Someone". A one-off migration (`convex/migrations/backfillAutomationConversations.ts`, server-secret gated, paginated) clears `conversationId` values that point at non-`isAutomation` conversations, restoring hijacked threads to their owners.
- `bin/convex-bootstrap.sh` rejected admin keys for non-default `INSTANCE_NAME` — the key prefix is `<instance-name>|`, not hardcoded `convex-self-hosted|`. Also `convex.env` (which holds real secrets) is now gitignored, as is `examples/*/node_modules/`.

### Removed

- **Bespoke Postgres application-data path**: Overlay is now Convex-only for application data. Deleted the `OVERLAY_PROVIDER_DATABASE` selector, all `Postgres*` repositories, the Drizzle app-data schema/migrations (`migrations/`, `drizzle.app-data.config.ts`), the app-data worker/scheduler (`scripts/db/app-data-worker.ts`, `app-db:*` npm scripts, `docker/docker-compose.app-data.yml`), the Postgres contract/parity suites, and the Postgres-only Next.js Stripe webhook (`/api/webhooks/stripe` — the `@convex-dev/stripe` component endpoint is the single webhook). Client-side Postgres long-polling was removed from chat/collaboration providers (Convex subscriptions only). Postgres remains in exactly two infrastructure roles: Better Auth's separate `BETTER_AUTH_DATABASE_URL` database (`pg` driver + `better-auth:db:*` scripts + compose service unchanged), and `@workflow/world-postgres` for durable workflow runs. Self-hosted/enterprise deployments run the official `convex-backend` (see `examples/customer-deployment/`); its persistence engine may itself be Postgres, which is a Convex-backend concern, not an application-data provider. `drizzle-orm`/`drizzle-kit` dependencies removed; `pg` retained for Better Auth.

### Changed

### Changed

- Redesigned the auth screens (`/auth/sign-in`, `/auth/sign-up`, `/auth/forgot-password`, `/auth/reset-password`) around a split layout — a quiet brand panel with the orb mark and tagline on desktop, a compact brand mark above the form on mobile — replacing the floating card. Auth options and the SSO capability flag are now resolved server-side during page render instead of two client fetches (`/api/auth/options`, `/api/v1/capabilities`), so the full form paints on first load rather than popping in after the heading. Sign-up's explicit Terms/Privacy toggle is now standard implicit-consent fine print ("By continuing, you agree to…"); the legal acceptance payload with document versions is still recorded identically at click time. The column scrolls safely when the form exceeds viewport height. ### Fixed

- Managed sandboxes no longer burn provider budget while idle. Vercel sandboxes have no native idle-stop — they run until the 24-hour `timeout` — so every managed lease provisioned ~96 GB-hours/day of memory whether or not the agent was used. The meter now enforces the lease's idle window itself: a sandbox with no acquire/settle activity for `idleTimeoutMs` (15 minutes) is stopped while the lease stays resumable, turn-slice acquires heartbeat `usage.lastActiveAt` so working sandboxes never cool mid-turn, and `running` leases past their 24-hour `reservedUntil` are reaped instead of lingering forever.

- The reconciliation sweep no longer emits recurring `offline_environment` warnings for managed (`overlay_cloud`) environments. Those environments have no heartbeat host — they read offline whenever their sandbox is idle-stopped, which is normal — so the BYO-oriented stale-environment pass now skips them in both the Convex and Postgres implementations. Genuinely stale BYO environments still alert.

### Changed

- Managed sandbox billing now meters the lease, not the turn. Agent-environment turns previously reserved a worst-case 24-hour sandbox cost (~$15) at dispatch, which declined turns outright on wallets that could have run for hours. `ManagedAgentSandboxBilling.reserve` now takes only a ~$1.50 bootstrap hold (low-balance floor plus a short coverage window), and a per-lease meter debits actual provider usage once a minute: each tick reads `instance.usage()`, diffs it against a cursor persisted on the lease (`usage.meteredUsage`/`meterVersion`), and commits the charge plus cursor atomically so retried or concurrent ticks can never double-charge. When the payer's remaining balance falls under $1 (`OVERLAY_SANDBOX_LOW_BALANCE_CUTOFF_CENTS`) or a tick debit is declined, the lease flips to `stopping`, in-flight commands and queued/running turns are cancelled with a `usage_limited` terminal error, and the provider sandbox is deleted by a reaper pass that also retries `cleanup_failed` leases with backoff — closing the gap where `stopping` leases were never reaped. Turn settle is now just the final meter tick plus bootstrap-hold release, and the missing `agentSandboxSettlements` marker on managed-harness settles logs at info instead of throwing `MANAGED_SANDBOX_SETTLEMENT_MARKER_MISSING` into reconciliation. The meter runs from the BFF `agent-environments/operations/reconcile` route (already called by the Convex cron) and the Postgres `app-data.maintenance` job; `OVERLAY_SANDBOX_METER_DISABLED=true` disables it. Provider usage reads never resume an idle-stopped sandbox (`reconnect(reference, {resume:false})` on every runtime adapter), and because providers such as Vercel publish cumulative counters only once a session stops, a running sandbox bills the elapsed window against a virtual wall-time cursor while reap/reset paths stop the instance, take one final meter read, then delete — so session usage is captured rather than lost at teardown. The 24-hour runtime hard limit, free-tier shape (30-minute cap, zero egress), and the standalone sandbox route's worst-case reservation are unchanged.

### Added

- Self-hosted Convex backend packaging for enterprise deployments (`examples/customer-deployment/docker-compose.convex.yml` + `convex.env.example` + `bin/convex-bootstrap.sh`, with the operations runbook at `docs/deploy-operate/self-hosted-convex.mdx`). The stack runs the official open-source Convex backend on PostgreSQL persistence and S3-compatible object storage with full feature parity to Convex Cloud — validated end-to-end against Overlay's real code path (full `convex/` deploy, 18 crons, storage upload/serve round trip, WorkOS/HS256 auth, AI Gateway chat). The architecture decision and proof results are recorded in `docs/develop/convex-only-self-hosting.md`.

- Managed harness providers, approvals, and BYOK (phase 4 of `docs/plans/MANAGED_HARNESS_AGENTS_PLAN.md`): Daytona is now a selectable managed-sandbox provider (`DAYTONA_API_KEY`; provisioned via a new `createOverlaySandboxProvider` bridge in `@overlay/sandbox-runtime` that maps `SandboxInstance` onto the AI SDK's `HarnessV1SandboxProvider`, with private preview links authenticated through `SandboxPort.headers`). Box remains deliberately unavailable for harnesses — it lacks the egress allowlist and credential-forwarding guarantees required to keep customer keys out of the sandbox. Approval-gated tool calls now park the durable workflow on a hook (up to 20 cycles per turn): the run row flips to `waiting_for_approval`, the existing approval card renders each requested tool, and resolving it resumes the workflow with synthesized `tool-approval-response` messages — no fallback to ACP. Managed harnesses can also run on a workspace member's own provider connection: the editor's **Model access** picker offers connections compatible with the harness's `byokProviders` (Vercel AI Gateway for Claude Code/Codex/OpenCode/Pi, OpenRouter for Hermes), the binding records `modelBilling:'byok'` + the connection and its owner, and the turn slice reads the key from the credential vault at execution time — the key never enters binding config, workflow state, or the Daytona sandbox environment. BYOK is restricted to the Vercel provider, whose request transformations inject the key at the sandbox boundary; other providers fail closed.

- Managed harness creation UX (phase 3 of `docs/plans/MANAGED_HARNESS_AGENTS_PLAN.md`): the agent editor's **Hosted on Overlay Cloud** branch now offers a runtime picker — the native Overlay agent plus every managed HarnessAgent this workspace may run (Claude Code, Codex, OpenCode, Pi, Hermes) — served by `GET /api/v1/agent-environments/managed` so the feature flag, `OVERLAY_MANAGED_HARNESS_ROLLOUT_STAGE`, workspace `allowedAgentHarnesses` policy, and Vercel Sandbox credentials all gate server-side (404 leaves Overlay as the only hosted runtime). Picking a managed runtime swaps the model/tool-group section for harness config — a per-harness model select (Overlay-funded; the harness-native alias lands on the binding's `adapterConfig.model` while the priced gateway model becomes `agent.modelId`), a fixed Vercel Sandbox provider row, and `/workspace`. Saving creates the agent, provisions the sandbox environment, then upserts the `protocolAdapter:'harness'` binding — a mid-flow failure lands on the edit page so retry never duplicates the agent. Editing a managed agent shows its runtime, live sandbox status, and a manager-gated **Reset session** action (`POST .../reset-harness` — clears `agentHarnessSessions` and destroys the sandbox; the next message rebuilds both). Switching runtimes provisions a fresh environment and resets the detached one; dispatch re-checks availability so a retired harness fails closed rather than turning on a stale binding. BYO agents keep the existing harness/environment/connect flow unchanged.

- Managed harness dispatch + durable turns (phase 2 of `docs/plans/MANAGED_HARNESS_AGENTS_PLAN.md`): messages to a `protocolAdapter:'harness'` binding now run through `managedHarnessAgentTurnWorkflow` instead of the ACP command queue. Each workflow step executes one time-sliced `@ai-sdk/workflow-harness` turn inside the lease's Vercel Sandbox — reconnecting or recreating it from the lease record — while a transcript writable projects stream chunks into the same generating reply row hosted agents use. `agentHarnessSessions.resumeState` carries the native session across user turns, and cancellation destroys the session, clears resume state, and settles sandbox billing. v1 runs built-in tools under `allow-all` inside the sandbox boundary with elicitation disabled; interactive tool approvals are a later phase.

- Managed harness provisioning (phase 1 of `docs/plans/MANAGED_HARNESS_AGENTS_PLAN.md`): `POST /api/v1/agent-environments/managed` now accepts `{mode:'harness', harnessId, provider?}` — it creates the Vercel sandbox (bridge port + allowlist egress with denied private/metadata CIDRs), writes an already-approved `overlay_cloud` environment with a fixed `/workspace` grant, and records the lease — no enrollment ceremony or Agent Host image. Bindings on those environments write `protocolAdapter:'harness'` (`AGENT_PROTOCOL_ADAPTERS` and `WORKSPACE_AGENT_HARNESSES` extended), and a new durable `agentHarnessSessions` store (Convex table + Postgres migration 0076 + both repositories) persists per-binding+conversation HarnessAgent `resumeState`. Live API verification is pending `VERCEL_*` env credentials — provider selection fails closed without them.

No routes or UI yet. A live smoke run verified a `claude-code` HarnessAgent bootstraps and streams inside a real Vercel Sandbox. - Automation runs now execute their agent loop as a durable in-workflow agent loop (`workflows/automation-agent-turn.ts` + `automations/automation-turn-runner.ts`) instead of the durable workflow shelling out to `/api/v1/conversations/act` over self-HTTP. Model calls, tool calls, message persistence, and billing run as individually durable and retryable workflow steps, so a process restart resumes at the failing step rather than losing the entire turn. Entitlement gating, catalog authorization, workflow-step metering, usage reservations, and run-status settlement are all re-evaluated inside steps under service auth; approval-gated tools are auto-denied with an explicit reason since unattended runs have no approval surface. The loop is manual rather than the SDK's `WorkflowAgent` specifically so the model resolves via `getLanguageModel` inside the step — **all providers work durably**, including BYOK keys (fetched from the vault at call time, never persisted in the workflow log), OpenRouter, and NVIDIA NIM.

- Computer agent tools (wiring phase 5.5): a new opt-in **Computer** tool group lets agents drive their bound persistent desktop — `computer_exec` (shell commands, 5m cap), `computer_read_file`/`computer_write_file`/`computer_list_files`, and `computer_open_url` (opens in the machine's real browser; the desktop stream ticket never enters the transcript — users watch via Open desktop). Deliverables (draft cards, gated callouts, generated files/UI) stay inline in both modes, and streaming still shows every step live in order. ### Fixed

- Saving an agent on a non-Claude managed runtime (OpenCode, Codex, Pi, Hermes) no longer fails with a bare `Request failed (500)`: the Convex `harness` validator in `collaboration/agents` and the `workspaceAgentDefinitions` schema only accepted `overlay`/`claude-code`, so arg validation rejected every other runtime before the handler ran. The union now covers the full `WORKSPACE_AGENT_HARNESSES` list, and a workspace-policy denial maps to a real 403 instead of an opaque 500. The dev Convex deploy was also unblocked by tolerating legacy/extra fields (`cancelAtPeriodEnd`, external-surface fields, `platforms`) as optional in the schema.
- The create-agent editor shows the runtime picker again for brand-new agents: creation inserts a draft row then opens edit mode, so locking the runtime on edit mode also locked it for never-saved drafts — drafts now keep the picker until first save while real edits stay locked.
- Managed harness turns survive a reset or expired sandbox. The environment lease stays `running` after reset while its provider reference names a destroyed sandbox; `ManagedAgentSandboxBilling.reserve` reconnected to it unconditionally, so every subsequent turn died at dispatch ("could not start this turn") before the workflow's recreate step could run. `reserve` now treats an unreachable sandbox as a zero-usage baseline (a recreated sandbox bills its full lifetime), and `settle` resolves the lease's *current* provider reference — the acquire step repoints the same lease when it recreates the sandbox. Sandbox settlement is also `.catch`-guarded on every path: it previously rethrew inside `finalizeManagedHarnessTurn` after the reply was already persisted, which marked the written message failed (hiding its text) and the run `model_failed`; the reservation's reconcile path now recovers the cents without failing the turn.
- A hosted agent's runtime can no longer be changed after creation. The runtime is the agent's identity — its environment, binding, and sessions are all per-harness — so the editor renders it as a fixed row; switching runtimes means archiving and recreating the agent.
- Agent saves no longer wedge on a failed computer provision. A `POST /boxes` flake left the bound row in `error` status with no provider ref, after which *any* save that touched the computer — including turning the toggle **off** — died on a 409 ("still provisioning") because `destroy` required a live machine ref. `destroy` now tolerates ref-less rows and treats provider cleanup as best-effort, provisioning retries the provider create once before erroring, and `provision` reclaims a dead `error`/stale-`provisioning` row (machine included) instead of stacking a duplicate on the owner binding — so retrying a failed computer setup actually provisions on the next save instead of failing forever. Server logs now record the underlying provider error for 5xx computer failures instead of swallowing it in `cause`.
- Archiving an agent now destroys its bound computer (best-effort): archived agents previously kept their machine — and its row — running and billing with no UI path back to it.
- Scheduled automations actually fire again. The `sleep()`-based per-automation scheduler workflow could not survive deployments (no durable workflow world is configured), so every enabled automation silently stopped running on schedule. Scheduled dispatch is back on the minute cron: `claimDueRuns` inserts a queued run and atomically advances `nextRunAt` (one claim per due slot — a run missed during downtime fires once late, not repeatedly), then each claimed run is dispatched through the same durable one-shot automation workflow as manual runs, with the workflow's own steps settling run status. `POST /api/v1/automations/{id}/start-scheduler` is now a deprecated no-op; the editor no longer calls it, and Postgres deployments keep their own `automation.schedule-due` job. Automations that were already enabled resume on the first cron tick after deploy — no re-saving needed.
- Image attachments in chat no longer fail to send: pasted screenshots and picked images were inlined as raw base64 data URLs inside the message JSON body, so a multi-MB image blew past the platform request-size cap and the send failed outright. Images are now downscaled to a 2048px edge and re-encoded as WebP client-side before attaching (GIFs pass through untouched since canvas encoding flattens animation; originals are kept when re-encoding can't beat them), with per-image and per-message size caps that surface a clear error instead of a failed send.
- Agent computer and agent-management tools no longer fail with `[tools] Tool not allowed` — `computer_exec`/`computer_read_file`/`computer_write_file`/`computer_list_files`/`computer_open_url` and `create_agent`/`update_agent` were exposed by `build.ts` but missing from the global `OVERLAY_TOOL_IDS` registry, so the defense-in-depth assert rejected every call. `COMPUTER_TOOL_IDS` now lives in `@overlay/tools-core` (re-exported by `tool-groups.ts`) so the registry and the agent group share one list, and a test pins every asserted id.
- Personal Chat Work mode no longer dies on tool schemas carrying JSON Schema `format` annotations: the workflow step that compiles tool schemas runs Ajv in strict mode and threw `unknown format "uri"` on tools like `computer_open_url`, failing every Work run that surfaced them. `format` keywords are now stripped when tool schemas are serialized for durable execution (they are advisory and do not constrain model input), and the chat banner now renders the run's real `terminalError` message instead of the generic "The run could not be completed".
- Settled assistant turns no longer hide answer text: the "Worked for N" collapse used to fold everything before the last text segment — including earlier answers — into the collapsed row. Work segments now fold behind one summary row at the top while every text segment keeps rendering in order, so `answer → tool call → closing line` shows both texts uninterrupted.
- Personal Chat Work mode now runs every model provider durably — BYOK keys, OpenRouter, and NVIDIA NIM no longer fail with `Unknown model: …`. The turn was the last `WorkflowAgent` caller: its internal model step resolved `gateway.languageModel(<id>)`, which only knows AI Gateway ids. `personal-chat-work.ts` now runs the same manual durable loop as automation turns — a `streamText` step rebuilds the model via `getLanguageModel` (BYOK credentials read from the vault at call time, never in the workflow log) and forwards live `ModelCallStreamPart`s so token-level streaming to the client is preserved — then one durable step per tool call, with the approval hook unchanged.
- Agent settings on the agents surface now docks as a right side panel (via the shell's `rightPanel` slot) instead of stacking under the conversation; dialog mode remains available as a toggle.
- Agent DM headers and message avatars now track the agent's live directory name — renames in the editor propagate immediately via `agent-directory-changed` instead of showing the stale "Untitled agent" snapshot stored on the conversation/participant records.
- Agent DM message rows now match personal chat: hover no longer paints a row background, and the action row reveals beneath the message instead of a floating rail at the top. Channels keep the Slack-style floating rail.
- Archiving a one-to-one DM no longer asks "for me or for everyone" — there's nobody else to keep it for, so it archives directly from both the conversation menu and the chat list. Channels and group DMs still ask.

- Fixed display-math fences glued to equation lines (`… × 100$$`) reflowing onto their own lines, stray `$` inside display spans repaired, and TeX grouping parens preserved inside single-dollar spans — sloppy model output now degrades to readable math instead of raw code.
- Fixed currency amounts being eaten by math rendering (`$20/mo **— $100…` tables): dollar signs followed by digits are now classified as currency openers and escaped unless the span carries explicit TeX structure, so prices survive KaTeX. Genuine digit-led math (`$2x + 1 = 5$`, finance examples) still renders.
- Fixed currency clauses containing hyphenated words being mangled into italic math (`$1.4M … For SV pre-seed, frame $` rendered "pre-seed" as a subtraction and let KaTeX eat the rest of the sentence): the math-minus heuristic now requires a spaced minus or single-char operands (`x - 1`, `a-b`), so multi-char word hyphens (`pre-seed`, `18-month`, `user-month`) stay prose.
- Fixed display equations clipping their bottom subscripts/descenders in chat and the notes editor: `.katex-display` is a horizontal scroll container whose tight bottom padding clipped glyph ink that overflows the last line box — bottom padding now absorbs it and the vertical axis degrades to a scrollbar instead of an invisible cut.
- The settled-turn collapse row now reads "Worked for {duration}, called N tools" and the duration survives reloads: it is derived from the assistant message's persisted `createdAt`→`updatedAt` span (the row is written `generating` at turn start and patched through settle on both backends), so reloaded agent replies and personal-chat turns show real timing instead of a bare "Worked".
- Message activity notifications no longer fire for a conversation you are actively viewing: the notification fan-out now skips any participant with a fresh online presence session parked on that conversation (the 45s presence heartbeat already reports it), so an agent answer arriving in the DM you have open does not also badge Activity.
- Fenced code blocks no longer render inside a second padded box: react-markdown wraps the block in `<pre>`, which carried its own background/padding around the code-block chrome — the renderer now unwraps `pre` when it directly contains the code block (bare fences keep the plain `pre` styling), preserving the stream-soften animation.
- Custom OpenAI-compatible providers no longer require an API key — the flag gates the dialog's Test/Save buttons, `POST /connections`, `POST /connections/test`, and the runtime gateway, so keyless endpoints can now be connected and used; when no key is stored no `Authorization` header is sent. (Note: OpenCode Zen's `/models` is keyless, but its completions still require an `OPENCODE_API_KEY` — its `*-free` models are session-locked to the OpenCode client.)
- Custom provider connections are easier to tell apart: the dialog's name field moved up under Provider as "Provider name" and auto-fills from the API base URL's host (e.g. `opencode.ai`) until edited, and connection rows show the endpoint host under the name instead of repeating the generic preset label.

- Pinned the Agent Host CLI restart/service hints, README, and launchd test to the released `0.3.5` line (they still pointed at `0.3.4`), and extended the release-gate script to assert all version pins together so the drift cannot recur.
- Fixed Workspace → People showing the authenticated provider user ID instead of the person’s profile name; existing member principals are repaired from the current browser session, and newly created workspaces start with the correct owner name.
- Allowed `data-remote-agent-commands` parts in the conversation message schema and BFF serialization: the Convex validator rejected connected-agent command events with 500s, and the BFF conversation serializer dropped the commands payload, leaving the agent DM slash menu empty after a page load.
- Fixed the agent DM slash menu ignoring typed input: the composer kept its live text outside React state by design, so the slash-menu hook only ever saw programmatically set text — typing `/` did not open the menu, filtering and selection did not update, and choosing a command left the menu stuck open. Typing now refreshes composer state only while a slash token is on screen, preserving the no-re-render-per-keystroke behavior for normal text.
